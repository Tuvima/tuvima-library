# Local check, 2026-11-03 (fresh start, real_media)

Walked with Shy on SHY-DESKTOP against main at 74d998cbd. Fresh start: data store, caches, profiles and collections moved to `%LOCALAPPDATA%\Tuvima\backup-2026-11-03-fresh-start`; API keys, tools, plugin config and settings kept. Nothing is fixed during the walk; fixes go to the cloud. Numbers are only for this file.

1. Setup welcome page (first page): the intro animation is great but sits inside a box; remove the outer box on this first page.
2. Setup welcome page: the Find / Connect / Enjoy icons and the "Private by default" icon have no colour. Shy wants one general colour scheme applied to all icons and buttons across the app, which currently feels dry.
3. Whole app: the page background should mostly match the intro animation's purple tones. Shy also sees pieces of green and doesn't know why. Wants the app colours unified (backgrounds, icons, buttons) so the whole app is uniform. Ties in with item 2.
4. Setup page 2: language and country should be enough; the Region field looks redundant next to Country. Needs a spec check on what Region is used for before removing it (decision for Shy).
5. Setup, Vault step: turning on the Vault shows its own "add libraries to the Vault" controls. Those should be folded into the one Libraries page (Vault-only kinds appear there as choices once the Vault is on). Related to 2026-11-02 item 7 (Vault before libraries).
6. Setup Libraries step, empty state: "No libraries yet" and "Add a library for each kind of media you own. You can add more later in Settings." run together with no space between the heading and the sentence, and the block needs better formatting (heading, spacing, an obvious Add button).
7. Setup Libraries step, Add library: after choosing an area (Watch, or any other) and pressing Next, the next pop-up opens off-centre. Every step of the add-library dialog should stay centred.
8. Setup Libraries step, folder picker: still too narrow, and it looks like the old version rather than the updated design Shy expected (see 2026-11-02 items 6 and 8 and the target images). The library name should sit at the top and be more prominent. Needs a check of what shipped against the Library setup spec and mockups.
9. Libraries page: each library shows its folder paths. Edit only lets Shy change the library name, with no way to add or remove folders. Wanted: show the number of folders, and clicking the number reveals the paths; Edit should manage folders. Shy says the earlier screenshots for this (2026-11-02 item 9, five target images) were never delivered, so this is a gap against the planned design, not a new idea.
10. Folder picker target design (Shy's image, `engineering/validation/local-check-2026-11-03/folder-picker-target.png`): wide dialog, "Step 3 of 4: Name your library & choose a folder", area and kind chips, library name field at the top, a folder path box with Go, a drives list on the left, a folder list (name, modified, arrow) with search and back/up/refresh, a "Folder accessible" line, "Your files are never changed", Back and Add library. Purple folder icons and accents throughout. Belongs with items 6 to 9 as one Libraries redesign.
11. Libraries page target design (Shy's image, `engineering/validation/local-check-2026-11-03/libraries-page-target.png`): "Library overview" with Add library button; an "In your collection" summary strip (coloured icons: movies, episodes, tracks, books); a scan-in-progress bar with "View activity"; "Your libraries" with colour-coded filter chips (All, Watch, Listen, Read, View), search, status filter and Cards/List switch; a list with library, area tag, count, a "1 folder" link, status (Healthy/Scanning) and Edit plus "..." actions; Edit opens a small dialog with library name, folder list with "..." per folder, Add folder, Cancel and Save changes; a View row at the bottom with Import folder and Configure. Answers items 9 and 10 and the colour theme in items 2 and 3: each area has its own colour (Watch purple, Listen pink, Read green, View teal), which may also explain the "green" Shy saw (Read).
12. Folder picker: while browsing it shows "This folder holds a folder that the library 'Movies' already uses. Choose a folder that does not overlap it." The picker should be dumb (just browse) and run overlap and other checks only at the end, when the folder is chosen. Same idea as 2026-11-02 item 8.
13. Setup Libraries, View area: Shy wants one choice, "Photos and Videos" (a dump of your phone), rather than separate Photos and Personal videos kinds, unless they behave differently. Decision for Shy after a spec check on whether the two kinds differ in the app (spec decision: keep both, or merge).
14. View: adding a folder for personal photos asks for a folder name, which makes little sense for "all your photos". Shy's model: View has a managed Shared photos location with each user/profile's managed photo location beneath it; extra folders added to View are indexed and aggregated into a general (not per-user) library; photos can then be moved from that library into the Shared library. This is a design change to how View works, so it needs planning (Shy flagged it for a Fable review of the mechanics, which needs Shy's approval per model routing). Related: item 13.
15. Settings, Metadata providers: the planned single page for entering and reviewing provider keys isn't there. The page's pills are misaligned and still rounded (Shy was told pills would be square and uniform). Shy asks what happened to those changes. Finding so far: the "One shared look" spec (pills, tabs, cards) and the Plugins and Integrations v5 spec are both marked Built, awaiting Local checks, but neither one names the Metadata providers page, so it may never have been in scope. Needs a check of which spec was meant to cover provider keys and which pages the shared pill style reached.

Finding: the kept secrets file for SubDL is byte-for-byte identical before and after Shy retyped it, so a matching key was already saved and "Key saved" was accurate for the file. So the page probably did not treat the stored key as usable (it still asked for one). Needs reproducing: what the page showed and whether it still asked for a key after "Key saved".
