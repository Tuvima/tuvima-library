## Plain-English product walkthrough

**What it feels like today.** Settings > Libraries is one screen: a list of types on the left (Books, Audiobooks, Movies, TV Shows, Music, Comics, Videos, Import folder, Other libraries) and that type's folders on the right. Photos and home videos live on a different page behind a small link at the bottom ("Personal photos & videos settings"). Adding a folder asks a different question depending on where you started. A new person has to know which of nine words fits their folder before they can begin.

**What it feels like after this spec.**
1. You open Settings > Libraries and see **five big cards: Watch, Listen, Read, View and Vault** (Vault only while Vault mode is on). Each card shows an icon with its colour, the types inside it, and a green tick or an amber warning if a folder needs attention.
2. You click **Watch**. You now see the things you can add there: **Movies, TV Shows, YouTube** and **Other videos**. YouTube has its own icon and its own rule: everything in that folder is looked up on YouTube, and any file that isn't a YouTube video is marked Unmatched and tried again later. Each row says how many folders and titles it has. Clicking a row opens the folder table you already know.
3. A single **+ Add folder** button works from every level. From the front door it asks three quick things: **What is it?** (pick Watch, Listen, Read or View, then the kind), **Which folder?**, and **How should Library treat it?** (Read-only is the recommended default). From a type page it skips the first question.
4. First-run setup uses the same words: **"What do you have?"** with Watch, Listen, Read and View to tick, then Add folder for each kind. Vault is never offered there.
5. Personal videos live only under **View**; adult videos only under **Vault**. Every kind of video has one clear home, and a future type such as Podcasts simply appears under Listen.
6. The Import folder stays, as one quiet row under the cards.
7. Nothing about how folders behave changes: Read-only and Managed, "New media goes here", Merge, Recycle bin and its 90 days all work as today.

**What stays the same:** every setting, every folder, the folder picker, the safety checks, phones being read-only for folders, and no new management screen.

## 1. Goal

Make it obvious where to put a folder and what Library will do with it, by leading with the five areas people already know (Watch, Listen, Read, View, Vault) and showing, inside each, the things they can add.

## 2. Scope

**In scope**
- A new Libraries front door of group cards, a group page per group, and the existing folder table as the type page (drill-in with a breadcrumb).
- One **Add folder** wizard of at most three steps, used from every level and from first-run setup.
- First-run setup step "media folders" reworded and reshaped as "What do you have?".
- Folding View's separate page ("Personal photos & videos settings") into the View group.
- A Vault card that appears only while Vault mode is on (see Q1).
- Folder health shown as icons (tick, warning) rather than words in pill-boxes.

**Out of scope**
- **Vault sections as full libraries, per-section access, on-disk separation checks and Move to Vault** are a separate follow-up spec (a separate Draft, not yet in the repo); this one only makes sure the groundwork fits it (D25).
- Any change to how folders are managed, merged or deleted. (Identification changes only as D17 to D21 say.)
- Creating several libraries of one type (still one library per type with many folders, Shy 2026-10-21).
- New library types. Documents and "Other libraries" keep today's placement (Q3).
- Native, TV and phone editing of folders (phones stay read-only, D23 of the Folder picker plan).
- Copying Plex's layout, colours or wording.

## 3. Decisions made

(All are proposals until Shy locks the spec.)

- **D1. Lead with the five areas, not nine type names** (Shy's idea, 2026-10-21). The areas match the app's own navigation (Watch, Listen, Read, View, plus the Vault), so people already know the words. Reason: Ease of use.
- **D2. Drill in, don't add menu items.** Libraries is one Settings page with three levels (front door, group, type) and a breadcrumb. The Settings menu tree is unchanged (Settings revamp D2, D35). Reason: Uniformity; no new menu entries for admins to learn.
- **D3. Still one library per type.** Groups are only a way to present the types; a group has no folders of its own. A type belongs to exactly one group, taken from the area it already has in code (read, listen, watch). Reason: Maintenance; no change to the data.
- **D4. Which types sit where:** Watch = Movies, TV Shows, YouTube, Other videos. Listen = Music, Audiobooks, Other audio. Read = Books, Comics, Other reading. View = Photos, Personal videos, Documents (D36). Vault = Adult content, and Videos, Pictures, Audio, Books and documents under a Private heading (D20). Reason: matches the Videos spec (D1, D2, D45) and presentation rules.
- **D5. One "+ Add folder" button at every level; the wizard skips what it already knows.** Front door: three steps. Group page: step 1 starts on that group. Type page: step 1 is skipped. Reason: Ease of use.
- **D6. Step 1 absorbs the Videos two-card choice** (Videos D3). Choosing Watch then YouTube, or View, is that choice; the Add folder dialog no longer asks it separately. The phone-footage hint moves to step 2 and offers a one-tap switch to View before anything is created. For folders already added, Videos D6 stands: remove and add again under the other choice.
- **D7. Step 3 is today's choice, in friendlier words.** Read-only (recommended), Merge into the managed folder (shown only when one exists and the folder has files), Let Library manage it. Same three outcomes as the current dialog; only the labels get icons and shorter text. For a new empty folder, the step asks only whether new media should go here.
- **D23. In step 1 the kinds are shown as options, each with an (i) circle** (Shy, 2026-10-21). There is no "What kind of Watch?" question: choosing a group tile simply lists its options as cards (for Watch: Movies, TV Shows, YouTube, Other videos). Each card has a small (i) icon that opens a tooltip saying what belongs there ("Feature films, one file or folder per film"; "Saved channels and downloads with a YouTube ID in the name"). The tooltip opens on hover, keyboard focus and tap, and the card itself stays one click. The Vault tile is the short name "Vault" and is drawn only when D13 allows; its options are Adult content, then the Private kinds, in two labelled groups.
- **D8. Type-specific extras sit in step 3, not in extra screens:** YouTube shows a short privacy line (only video IDs are sent, Videos D7) and the optional personal YouTube key; View shows its own options (subfolders, photos); a Vault folder shows the adults-only confirmation and the administrator PIN check (Videos D25, D34).
- **D9. Few pill-boxes, icons with colour** (Shy's UI style). Health is a green tick or an amber warning icon with a tooltip; Read-only and Managed are icons with a short word on hover and in the table, not boxed chips. The local-check fixes already moving the Read-only pill to an icon are adopted as the rule.
- **D10. Group and type pages centre like the other Settings pages, with no repeated heading.** The breadcrumb is the only place the group name appears above the title. Reason: Uniformity.
- **D11. Recycle bin stays per type and pinned at the bottom of the type page** (Videos D49, Delete groups D12 and D18), including its days setting. The front door shows no bin controls.
- **D12. First-run setup:** the "media folders" step becomes "What do you have?": tick Watch, Listen, Read, View, then Add folder for each kind with the same wizard. Skip for now stays (it defers the step exactly as today). Vault is never offered in setup. The step keeps its key, so the stepper, deferral and resume behave as they do now.
- **D13. The Vault card obeys the Vault's privacy rules.** It is drawn only for an administrator who has turned Vault mode on in this device session and whose profile may see the Vault; otherwise there is no card, no word and no hint (Videos D17, D45). Creating the first Vault folder still needs the administrator PIN (Videos D25) and the adults-only confirmation (D34).
- **D14. Folder health uses what the Engine already knows:** healthy, "Folder offline" (a drive that can't be reached, not a deletion; Safer deleting D4) or "Needs access". A group's icon is the worst state of its folders.
- **D15. Phones show the groups and counts but hide Add folder and every edit control** (phones are read-only for folders). TV stays "unavailable", as today.
- **D17. A library type is a "recipe", and the folder you pick decides the lookup** (Shy, 2026-10-21). Each type is one entry saying: its group, its name and icon, its lookup source (or none), how files are named and grouped, and what happens to files that don't fit. Movies and TV Shows use their existing sources. **YouTube** is its own library under Watch with the YouTube icon and the YouTube lookup. Adding Podcasts later is one new entry that shows up under Listen and behaves like every other library. Reason: Extensibility and Uniformity; no special cases per type.
- **D18. Everything in a YouTube folder is looked up on YouTube; what isn't a YouTube video is Unmatched, not queued for review** (Shy, 2026-10-21, revised the same day). A file with a YouTube ID in its name or `.info.json` is matched; anything else in that folder stays where it is, marked **Unmatched** (D34). Nothing is looked up for files that never get an ID. Supersedes the earlier "goes to Needs Review" idea and moves back toward Videos D32 (doubtful items are never queued), now for every type (D34).
- **D19. Personal videos have one home: View** (Shy, 2026-10-21). Phone and home footage is added as View, never Watch. The Watch types are for structured, identifiable video.
- **D20. The Vault holds one adult kind and the private kinds** (Shy, 2026-10-21, revised: adult videos and pictures usually live together). **Adult content** is one kind for videos and pictures together; its provider is the Stash-box server (Videos D21, D26) and its tooltip says so honestly: as far as we know Stash-box covers videos (scenes), so videos are matched there and pictures in the same folder are organised locally as galleries (Videos D44) and not looked up (to confirm in the Stash terms check, Videos D29). **Private kinds**, listed under a "Private" heading so names need no prefix: **Videos, Pictures, Audio** and **Books and documents**, places to keep ordinary material private with no outside lookup (D38). Each kind is its own folder list. The Vault is still one area (Videos D45). Which kind has metadata and how its folder is handled are separate questions (D31). Reason: Uniformity and Ease of use; the Vault is for anything private, not only adult content.
- **D31. Folder handling and metadata are two separate choices** (Shy, 2026-10-21). **Folder handling** (Read-only or Managed) is only about files: Managed means Library renames files and folders, organises them (for pictures: into year and date galleries) and writes tags and details into the files; Read-only means it never changes them. **Metadata** is only about where details come from (the provider icon of D22, or none). Any combination is allowed: a Read-only folder still gets metadata; a Managed folder may have no provider at all (a Private pictures folder may be Managed with no lookup). Step 3 asks only about handling; the Metadata column shows the provider, and neither changes the other. Recommended defaults: Read-only for everything except where a destination is needed (a "New media goes here" folder, and the Vault kinds that moves will need later, where Managed is recommended). Reason: Ease of use and honesty; one word, one meaning.
- **D32. The Vault can be set up from one root folder, or folder by folder** (Shy, 2026-10-21). **Root folder:** the administrator picks a single folder; Library creates and manages a sub-folder for each Vault kind inside it (for example `Vault\AdultVideos`, `Vault\PrivatePictures`; names Library creates contain no spaces, Shy 2026-10-21), all Managed, and new kinds get their sub-folder automatically when first used. **Folder by folder:** the administrator adds individual folders on any drive or path, each Read-only or Managed (D31), exactly like other libraries. Both can be used together. A root folder must be separate from every normal library folder (Vault spec D29). A Managed folder for a kind is what a future Move to Vault needs as its destination (Vault spec D33). In Add folder, the Vault tile offers "Set a Vault root folder" first, then the kinds. Reason: Ease of use; one choice sets up everything, with the flexibility to add more.
- **D33. Types are provided, not hard-coded, so new ones are easy to add** (Shy, 2026-10-21, an overarching goal). A library type is one entry (D17) that a plugin can supply: its group, name and icon, its metadata provider, how files are named and grouped, and its folder handling defaults. A recorded TV type with its own metadata alignment, or a Podcasts type under Listen, is added by enabling a plugin; the front door, group pages, Add folder step 1 and the Metadata column are generated from the list of available types, with no screen changes. The built-in types ship the same way. The plugin side builds on the Developer tools spec's plugin system; the exact plugin surface is settled in WP7 with that spec's owners (to be confirmed). Reason: Extensibility and Maintenance.
- **D34. "Unmatched" is a state and a filter, not a review queue** (Shy, 2026-10-21). A file the Engine can't match stays exactly where it is, is marked **Unmatched**, and is tried again later without anyone doing anything: on a schedule (weekly by default, a setting), after a provider or plugin is updated or enabled, and on a **Retry now** button. Every library page gets an **Unmatched** filter so a person can look when they choose, with a count on the library row. Needs Review keeps its current job for the opposite case: a match the Engine found but is unsure about and needs a person to choose. Reason: Reliability and Ease of use; many users will have unmatched files for a while (a title not on a provider yet may appear in a month), and a long review list across libraries would overwhelm them. This changes behaviour for every library, so it is WP9, built with the Engine's identification owners.
- **D35. A safety break when most of a new folder doesn't match** (Shy, 2026-10-21). After a folder is added, once enough files have been tried (proposal: the first 50, or all if fewer), if more than half are Unmatched, identification of that folder pauses and the administrator sees one plain message ("Most files in this folder aren't matching: 212 of 300. This is often the wrong kind or the wrong folder.") with three choices: **Keep going and leave them Unmatched** (retry later, D34), **Change what this folder is** (back to Add folder step 1 for the same folder) and **Remove the folder**. Nothing is renamed or moved while paused, including in Managed folders. The numbers are settings in `config/`, not code. Reason: Prevent, don't patch.
- **D36. Documents are a View kind of their own** (Shy, 2026-10-21). View has three kinds with their own folder lists and their own permission: **Photos**, **Personal videos** and **Documents** (read locally with text recognition, which shows as its provider icon, "Local text recognition"). This fills the gap that Movies, Photos and Videos each have a place and Documents did not, and gives Documents a place to hold access (a profile with documents off simply isn't granted that kind; it never learns it exists). It splits what today's View folder treats as one list, so WP8 handles View's folder settings carefully. "Other libraries" is dropped from the new design (pre-release; Q3 recommendation unchanged unless Shy objects). Reason: Uniformity and Privacy.
- **D37. Explanations live in the (i) tooltip everywhere in folder and library setup** (Shy, 2026-10-21). Option cards (Add folder step 1 and the Vault step, step 3's Read-only, Merge and Managed, the Videos switches) show a name, a tick or icon and an (i) circle, never a second line of description; group-page rows show counts and status, never a sentence. The one exception is a warning icon (amber triangle, shown without hovering) on choices with a consequence for other software, such as Let Library manage it. Tooltips open on hover, keyboard focus and tap. Reason: Ease of use and the no-walls-of-text style.
- **D38. Every area has a plain kind for things that can't be looked up** (Shy, 2026-10-21). Watch: **Other videos**. Listen: **Other audio** (random audio files, recordings, lectures). Read: **Other reading** (loose books and documents with no match). View: its kinds are already plain (Photos, Personal videos, Documents; Documents read locally by text recognition). Vault: the Private kinds. A plain kind never contacts an outside service, never produces Unmatched noise, and shows files by folder and file name plus the tags inside the files (title, artist and so on), because without a catalogue there are no albums, series or shows to group by. Reason: Privacy and Ease of use; some files will never be in any database and deserve a proper home, not an endless Unmatched list.
- **D39. Colour shows lookup versus plain, backed by an icon** (Shy, 2026-10-21). On every library row and Add folder card, a kind that gets a metadata lookup has its icon tile filled with its area's colour and carries its provider icon (D22); a plain kind has a quiet grey tile and the grey "files as-is" icon. Colour is never the only signal: the Metadata column icon and (i) tooltip say the same thing, so colour-blind users and screen readers get it. The Adult content card follows the same rule (lookup colour).
- **D40. Mixed content: the library's kind decides the lookup, and nothing that doesn't match is lost** (Shy asked for the mechanics, 2026-10-21; my recommendation). (a) Someone can always drop non-matching files into a lookup folder: they play and browse like any title using their file names and tags, are marked Unmatched (D34), and are retried later. (b) **Keep as is** on an Unmatched item (or "Keep all Unmatched as they are" for a folder) stops retries and clears it from the Unmatched filter, so the list can be emptied; a later "Look up again" brings it back. (c) **Change what this folder is** on a folder's "..." menu moves a whole folder between kinds in the same area (for example Music to Other audio), with a plain confirmation, reusing the same action the safety break (D35) offers; this softens Videos D6 for a folder that is already added. (d) No per-folder "turn lookup off" switch: the kind already says it, and a second control would be two ways to say one thing. Reason: Uniformity and Maintenance; prevent, don't patch.
- **D41. An icon legend on every Libraries screen** (Shy, local check 2026-10-21). A single quiet line at the bottom of the front door, group pages and type pages lists the icons used there with a word each: Read-only, Managed, has a metadata provider, files as-is, warning, Unmatched. It is one row of icon-and-word pairs (no box, no paragraph), also reachable as an "Icon guide" link in the page's "..." menu; the tooltips on the icons themselves stay. Reason: Ease of use.
- **D42. The "Pictures" gap is closed by View's Photos kind** (Shy, local check 2026-10-21: "there is no pictures library listed"). Today photos live on a separate page, so the Libraries list shows none. With View as a group (D4, D36) Photos appears as its own row with its folders, like Movies. Local check L13 confirms it.
- **D43. The folder picker behaves like a Windows Explorer address bar** (Shy, local check 2026-10-21, with a screenshot of Explorer). The path at the top is a row of clickable folder names; the drive is shown once (not twice); each segment has a small chevron that lists the folders inside it so people can jump sideways; clicking in the empty space at the end turns the bar into editable text where a path can be typed or pasted, with Enter to go and Esc to cancel; and the list below gets more room (taller rows, more padding) so it no longer feels thin. Applies to every place the picker is used (Add folder, Import folder, Vault root). Reason: Ease of use; people already know this control.
- **D44. Drag and drop to add files on library pages** (Shy, local check 2026-10-21; Shy asked whether it can be done reliably for big files). **How it works:** dropping files on a group page or type page (or choosing Add files; touch devices get the button only) uploads them to the Engine, which saves them in the Import folder under the matching kind's sub-folder and files them by the normal rules. The Engine receives them over a normal web upload, not through the live Dashboard connection, which is meant for small messages. **No silent success:** if no Import folder (or no Managed destination for the kind) exists, the drop is refused with one plain message and a link to set it up; a file is never accepted without a destination. (This is the reverse of the bug Shy saw, where a photo was accepted with no folder defined and then could not be found; that bug itself is being diagnosed in the local check.) **Wrong page:** each dropped file is checked quickly (file type and, for media, the video or audio streams and length); if it doesn't fit the page (a film dropped on Listen), a small dialog says what it looks like ("This looks like a movie, not music") and offers the kinds that fit, as the usual cards with provider icons and (i), including a plain kind; the choice decides how it is looked up. Several files are grouped in one dialog. **Reliability, honestly:** I haven't tested large uploads on this code. Browser uploads of small and medium files (photos, songs, books, episodes) are dependable. Multi-gigabyte films are riskier: one dropped connection restarts a plain upload, the file is stored twice while it moves, the browser cannot hand over a file's path (only its contents), and proxies may time out. My recommendation: build chunked, resumable uploads with a progress bar and Cancel; run a spike first that uploads 1, 10 and 50 GB over the local network and measures time, memory and recovery after an interruption (WP11); **Shy's rule (2026-10-21): aim to support big files, the way YouTube does, if it can be made reliable; where it can't, say so.** So the target is resumable chunked uploads that survive a dropped connection and carry on, with progress and Cancel. Whatever size the spike proves reliable (a setting, proposed 4 GB until measured) uploads normally. Above that, the upload is still allowed but an amber warning box appears first: "Large uploads can fail. For files this size, copying straight into the Import folder on the server is more reliable," with the folder's path and a Copy path button, and Upload anyway / Cancel. If the spike shows resumable uploads work well at all sizes, the warning never appears. Only administrators can add files this way, and dropping on a Vault page needs Vault mode (D13). Reason: Reliability and Ease of use.
- **D45. Plugins add library types as settings, not code** (Shy, 2026-10-22). A plugin supplies a type as a declarative entry (group, name, icon, lookup source, naming and grouping rule chosen from the built-in ones, misfit handling, folder defaults), the same way plugins already add metadata sources; it cannot run code. The built-in types (Movies, Books and the rest) ship as the same entries in Library's own configuration, so one list drives every screen. A type that needs a new way of grouping files still needs a Library release. Settles the WP7 open point in D33.
- **D46. View folders can be added during first-run setup, and they default to the whole household** (Shy, 2026-10-22). Ticking View in "What do you have?" offers Add folder like the other areas; a folder added there goes to the household's shared View library by default, with the person's own personal space as the other choice. Built as WP13 after WP8.
- **D47. Every profile has its own space, and everyone can add to the shared one** (Shy, 2026-10-22). A second profile can sign in, pick their profile and start backing up their pictures and documents to their own personal gallery and documents; everyone in the household can also add photos and documents to the shared libraries, so the things that really matter stay in one place.
- **D48. Each View item records which profile added it, shown as the profile name** (Shy, 2026-10-22). The tag is just the profile name, never a sentence such as "Added by …"; shared galleries can be filtered by it, so pictures from profile A, B and C can be shown separately. For files found in a folder, the profile is the one that added the folder; for uploads and backups, the uploading profile. It is written into the file too when the folder is not read-only. Part of WP8.
- **D49. View kinds: folder kind, permissions and misfits** (Shy, 2026-10-22). Each View folder has a kind (Photos, Personal videos or Documents). Existing View settings and data may simply be cleared: re-ingestion is the default, so no conversion is built. Photos and Personal videos each get their own on/off per profile, like Documents already has. A folder accepts only what fits its kind (Documents: PDFs and pictures of paper; Photos: pictures; Personal videos: videos); other files are skipped and counted on the folder's row, never moved or deleted.
- **D50. WP7 goes before the Videos Vault wave** (Shy, 2026-10-22). The Vault's Adult content and Private kinds (D20) are added as ordinary type entries when the Vault work lands.
- **D51. Custom libraries can be named, and there can be several** (Shy, 2026-10-22, approach decided by Claude at Shy's request). The lookup kinds (Movies, TV Shows, YouTube, Music, Audiobooks, Books, Comics) stay one library each (D3). The plain kinds (Other videos, Other audio, Other reading) allow up to five libraries each, every one named by the person ("Lectures", "Family recordings"), so nothing is lumped together unless the person wants it. Each named library is its own row on its area's group page and its own browse tab (D54); Add folder offers the existing ones and "New custom library". This replaces the "still one library per type" line in Out of scope for the plain kinds only.
- **D52. The shared library keeps who contributed each item, and it can be filtered by that and by tags** (Shy, 2026-10-22). A photo or document that moves into the shared library from someone's own space keeps the contributing profile as its "added by" profile (D48), never the administrator who accepted it. The shared gallery and documents can be filtered by who added them together with tags; tags and smart galleries (rule-based, already in View) act much like folders. AI-built categories come later, out of scope here.
- **D53. The phone-backup and upload folders accept photos and videos together** (Shy, 2026-10-22). A camera roll holds both, so each profile's built-in backup folder and the shared library's upload accept pictures and videos; each item then shows under Photos or Personal videos by its own type, and a Live Photo's short clip stays with its photo. Every other folder follows D49 (it accepts only what fits its kind).
- **D54. Each kind, and each named custom library, gets its own browse tab, shown only when it has folders** (decided by Claude at Shy's request with D51, 2026-10-22). Watch shows Movies, TV Shows, YouTube and Other videos (or the custom libraries' names); Listen and Read likewise. A tab appears once that kind or library has a folder, so nobody sees empty tabs.
- **D21. "Other videos" is the catch-all under Watch** for courses, lectures and anything with no outside source: no lookup, names and folders only (the current Videos behaviour minus YouTube). Kept (Shy, 2026-10-21, Q5).
- **D22. A "Metadata" column shows each library's provider as a small icon** (Shy, 2026-10-21, replacing the wording "Looks up: …"). Lists carry a column header at the top (Name, Metadata, Folders, status) so each column explains itself. The Metadata cell holds the small icon of each provider the library uses (TMDB, MusicBrainz, YouTube, Stash-box and so on, from the provider's own brand icon). Hovering or focusing it shows a tooltip naming the provider and the details it supplies ("TMDB: titles, posters, cast, ratings, descriptions"). A library with no provider shows a muted "files as-is" icon whose tooltip says "No online lookup. Files are added as they are." No sentence of text sits in the row. ## 8. Risks and open questions

- **Risks:** cross-system folder rules for the Vault root and its created sub-folders: Library checks before creating anything that the root is writable, is not already inside a normal library, is not a reserved system name (Windows names such as CON or NUL, trailing dots or spaces), is short enough for Windows' 260-character limit, and does not collide with an existing folder that differs only by capital letters (the Folder picker plan already treats a case-only difference as the same folder on every system). Docker setups need the root inside a mounted volume. Created names use letters and digits only (`AdultVideos`), so they behave identically on Windows, macOS and Linux and in shell scripts. `LibraryFoldersPanel.razor` is large (about 1,200 lines) and shared with first-run setup, so splitting it can break either place; WP2 and WP4 tests cover both. People who know the old left-hand list lose it; the front door adds one click for the same destination (Performance of understanding over speed of clicking; today's list stays one level below). View has its own folder store, so its wizard path hands off to View's add flow rather than the shared one.
- **Resolved (2026-10-21):** "Other videos" is kept (D21) and non-YouTube files in a YouTube folder go to Needs Review (D18). The Videos spec needs a version bump for D2 to D5, D26 and D32 when this is locked.
- **Next spec: Vault sections and Move to Vault** (a separate Draft, not yet in the repo). Carries Shy's answers on Vault kinds that are full libraries, per-section access, on-disk separation and moving items in. This spec stays lean and does not depend on it, except that the Add folder step lists the extra Vault kinds as they arrive.
- **Resolved (2026-10-21):** the Vault card appears in Libraries while Vault mode is on, which amends Videos D45's "Vault settings live only inside the Vault area" (Q1, settled by Shy's thin red-bordered card and Vault tile requests); drill-in pages (Q2); first run is tick what you own (Q4); Documents become a View kind (D36, Q3). ## Plain English summary

Settings > Libraries gets a front door with five cards: Watch, Listen, Read, View and, only when you've switched on Vault mode, the Vault. Click one to see the things you can add there (for example Movies, TV Shows, YouTube and Other videos under Watch; personal videos under View), and click again for the folder list you already know. One Add folder button runs a short three-step guide: what is it, which folder, and whether Library should leave it alone (the recommended choice) or tidy it. First-run setup asks the same simple question, "What do you have?". Nothing about how your files are read, kept or deleted changes, and the Vault stays completely invisible unless you've turned it on.
