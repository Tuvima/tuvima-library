Per CLAUDE.md "Never" 10, this spec does not rewrite the body of the Locked v4 or v4.1 specs. It amends them; section 9 lists every line that changes and Shy's recorded override.

## 0. Why

Shy's local check of 7 Nov: "the main editor page looks terrible and doesn't properly support the structure of shows, videos, etc." The v4.1 editor still lists children in a Contents tab and files in a Files tab, the episode chooser wraps and shows no stills (bug 20), an episode of a video folder will not open (bug 21), the Match tab text-searches the show's own title and reports "Nothing called …" for a show that is matched (bugs 24, 25), and the Steph Curry MasterClass workbook has nowhere to be named, grouped or described. Shy supplied four directional mocks (an episode editor, a course worksheet, a season character guide and a 238-file picker) and a set of decisions, recorded in section 3.

## 1. Goal

One editor that reads like the item itself: a large cover and the item's title at the top, with the way around a show, course or album built into the header (home, Season or Section, item), and nothing to learn below it but Details, Artwork, Match and History. Every file that sits beside your media (a guide, a worksheet, a featurette, a zip of starter code) becomes a supporting file you can name, describe, group and place, found through the same header, on the details page and in Search, whether a show has two of them or two hundred.

## 1a. Plain-English walkthrough

### The header is the map
1. **Press "…" then Edit** on an episode. The window opens over the dimmed page. Top left is a **96 × 144 cover**, a picture only (it does not navigate). Beside it, the show's name as a **plain label** (not a link, no chevron), then the episode's title and one line of facts with its match state. Top right: the provider links with logos, the Wikidata link, and the close X. There is no kind label above the title.
2. Under the title, one row: a **home button** in the accent colour (the breadcrumb back to the root, and the only way up), a **Season** dropdown, and an **item** dropdown. The item dropdown shows each episode's **still, code (S02E03) and title**, with a tick when matched, a warning when not, and a purple dot when changes are waiting on it. It is searchable and pages in for long shows.
3. Below the episodes, the same dropdown lists the **supporting files that belong to this season** (type badge, title, group), then **All supporting files** (which opens the browser, screen E, when there are more than eight), and last a **folder button, "Browse files and folders"**, which opens the real folder tree so any file the Engine found can be reached, sorted or not.
4. **A course** (a Videos series) uses its own words: the second dropdown is **Section** (the sub-folder), videos show a number and a length, never "S01E02", and the tick means watched (a course has no provider match).
5. **A movie** has no home button, no Season and no Episode. It shows the item dropdown only when it has supporting files (the movie itself, then its trailer and featurette); with none, the header ends at the facts line. A standalone book and a person behave the same. The label line then says the kind ("Movie", "Book").
6. **An album** shows home (the album), no second dropdown, and the track dropdown. **A book in a Series** shows home (the Series), no second dropdown, and the book dropdown. **A Universe** keeps its kind dropdowns (v4 D10).
7. **Tabs are Details, Artwork, Match, History.** There is no Contents tab and no Files tab. A supporting file gets **Details, Preview, History**. A Series gets Details and History, read-only (item 15).

### Details, locks and the footer
8. Every provider-filled field is **locked by default** (dimmed, dashed border, a lock in accent colour beside the label). Click the lock to unlock and edit. A value you change is kept on every later provider refresh (it becomes yours), and shows Revert. Your own fields (tags, sort title, supporting-file fields) are never locked.
9. **Quick facts** stay beside the form, in the accent card: match state, the file's quality, container, size and folder (there is no Files tab any more, so the file's facts live here), last refresh, and on a container the count of supporting files.
10. The **header background is a gradient** built from the cover's two main colours (the Engine already extracts them for every picture). No banner artwork, no picture to download; a cover with no colours yet gets the neutral near-black.
11. The **footer** reads, left to right: a red **Delete**; the file status **"File write-back off — Edits save in Tuvima. Original files stay unchanged."** (or "File write-back on — Edits save in Tuvima and are written into the file's own tags."); the unsaved count; **Discard**; **Save changes**. A match that will move a file in a Managed folder replaces the status with the amber warning from v4.1 D6 until you save or discard.

### Supporting files
12. **What they are.** Any file inside a title's folders that is not the main media and not a sidecar: documents (PDF, text, EPUB), pictures, clips and audio: only kinds Library can open. Archives, `.nfo` files, subtitles and other sidecars are never supporting files (D16). Today these are "Extras" with a kind and a place; they become **editable items** with a title, description, group, role, scope ("Belongs to"), an optional "Shown alongside" episode or lesson, and tags. Nothing about this moves, renames or rewrites a file.
13. **Where a file belongs is read from its folder.** In the show's root folder: the show. In a season folder: that season. Named after an episode's file or sitting in a folder named after it: that episode. In a course: the series, the section, or the lesson whose number and words it shares. Belongs to is a plain dropdown (the show, each season, each episode); under it a hint says where the value came from: "From its folder location" or "Set by you". There is no separate Override control (Shy, 2026-11-07 05:51Z): changing the dropdown is the override, and a value you set is kept across rescans. **Changing Belongs to moves the file** in a Managed folder (into the season's or episode's folder, with the amber footer warning, on Save), exactly as a changed match does (v4.1 D6); in a Read-only folder the file stays where it is and only its place in the Library changes. **Grouping is virtual**: a group is a name you give ("Character guides", "Homework"); it never depends on, or changes, the folder layout.
14. **Group is a type-in box** (Shy, 2026-11-07 05:52Z), the same control as Tags: click in, the title's existing groups drop down, typing filters them, Enter or a click picks one, and a name that matches nothing offers **Create "Week 1"** as the last row; the arrow opens the full list without typing. The group is created on Save (Review lists "Create group"). **Roles are a short fixed list by type:** documents are Guide, Worksheet, Transcript, Notes, Booklet or Other; videos are Trailer, Featurette, Behind the scenes, Deleted scene, Interview or Clip; pictures are Pictures. The role is guessed from the file and folder names (as v4 D20 already does) and only pre-fills. **Suggest details from the document** fills Title and Description from the file's own metadata and first page, on your machine, with no provider.
15. **Two kinds of folder, one rule.** A matched show or movie with a few files beside it and a course of forty lessons with worksheets are the same thing to the Engine: files with a scope, a role and an optional group. What differs is the **default presentation**: on a matched title the details-page row is called **Extras**; on a course it is called **Materials** (Q1). Files in a lesson's folder are tied to that lesson automatically (item 13), so a course page shows "Worksheet · PDF" under each lesson without anyone sorting them.
16. **Scale.** Up to **8** supporting files at a scope appear inline in the item dropdown; above that the dropdown shows "All supporting files (N)" and the **browser** opens: search over file names, titles and descriptions; a **Where** filter (whole show, show level, each season, each episode); a **type** filter; a left list of your groups with counts and "Ungrouped"; a table with ticks; paging at 25 a page; and bulk actions on ticked rows (**Set group, Set role, Belongs to, Add tags, Delete**). **Edit selected** opens the editor as "Editing N files" with only the shared fields. On the details page the Extras row shows at most 12 cards per group and a **See all N** that opens the same list read-only. Ungrouped files are still shown; grouping only tidies.
17. **The default needs no work.** A show with a handful of files looks as it does today (one row, no group headings). A show with many files is grouped by role family until you name groups. Nothing lands in Needs Review (Extras D5 stays).
18. **Search** (the main search box) finds supporting files by title, description and file name, under a "Supporting files" section, following the same visibility rules as the title they belong to.

### Match, series and Universes
19. **Match has two options at the top: Media providers and Wikidata.** Media providers is the retail match (TheTVDB, TMDB, MusicBrainz, OpenLibrary, ComicVine, Apple, YouTube); Wikidata is the canonical identity. They are independent: changing one never touches the other, and the tab flags it when the two disagree. You always match **the item selected in the header**, nothing else.
   - **An item that is matched** shows the current match first, found by its provider ID: picture, title, year, creator, provider name, **Open source**, **Change match**, **Remove match**, and a **Why this match** table (your file against the matched record, one row per fact, with a Strong / Possible / Check label). It can never say "Nothing called …" about its own title.
   - **Change match** opens a compact search in place: one provider dropdown (the default provider first, each with its status), fields that suit the type, the original file name as muted text, and clean, editable values pre-filled from the file name, embedded metadata and folder hints. A search runs when you press Search or change a field, never on opening. Results, a preview of the selected result, local evidence beside it, a verdict with reasons, and **Apply match**. Apply is always allowed, even when the evidence disagrees.
   - **TV:** find the show first (the show card has Change show, which works even when the file sits in the wrong folder), then a text list of that season's episodes (number, title, air date, runtime) with the episode suggested from the file name and the measured duration.
   - **Music:** search by artist, album or song; pick the album or release, then the disc and track. Choosing a track from another album moves the song there and renumbers it; the change is previewed first, and recordings say whether they are the original, a remaster, a live take or an edit.
   - **Local videos, courses and supporting files** offer a match only where a provider supports it (a YouTube ID); otherwise the tab says plainly that the details stand on their own.
   - **Wikidata:** a clean search and a box for a pasted link or QID; text-only results (label, description, kind, QID, a distinguishing fact); alignment evidence from known IDs, title, year or creator; and a clear line between a direct item and its parent (a show is never assigned as an episode's identity).
   - There is **no "Change placement"** (matching an episode elsewhere moves it, and in a Managed folder its file) and **no batch line-up table**: files are matched one at a time from the header. Applying a match updates unlocked fields, keeps locked ones, writes History, follows the library's file-management mode, and pins the match so a later scan never re-identifies the file from its folder. Section 3c has the detail.
20. **A Series is read-only everywhere.** Edit on a Series shows its name and ordered members locked, a notice explaining that a Series is a canonical grouping that comes from the members' own matches, the dropdown to reach a member, and Close. No Artwork tab; the shelf uses the automatic stack of its members' covers (Q3).
21. **A Universe is mostly read-only**: its Details unlock only for added details and overrides (description override, aliases, extra pictures); provider facts stay locked with no unlock.

## 2. Scope

**In scope**
- New header (cover, label, title, facts, links, home, Season/Section dropdown, item dropdown with supporting files and the folder button), the gradient, locks by default, Quick facts, footer wording and states.
- Removing the Contents and Files tabs; moving their jobs into the header, the browser and Quick facts; moving video-series ordering into the browser.
- Supporting files as items: data model, scan-time inference (scope, role, related lesson), overrides, groups, hidden sidecar types, "Suggest details from the document", the Preview tab, the browser with bulk editing, the details-page row with groups and See all, Search.
- Match tab rebuild (current match first, search on change, no Change placement, Match all files).
- Series read-only; Universe overrides only.
- Bug 21.
- Retiring the replaced pieces, guardrails, docs (Library repo and tuvima-docs), new versions of the specs and rules in section 9.

**Out of scope**
- Phone, tablet and TV editing. Photos and documents in View keep their editor (it inherits the new frame: Q5).
- New Universe kinds; Timeline.
- Provider-fetched extras; OCR beyond today's.
- The tooltip review (bug 27) and Look v2 follow-ups.
- Changing how episodes themselves are matched at scan time.

## 3. Decisions made

Shy's decisions of 2026-11-07 unless marked as a recommendation.

- **D1. Header navigation replaces the Contents tab.** Home button, Season (or Section) dropdown and item dropdown inside the header. Reason: one place to move around, and the list carries stills and codes (bug 20).
- **D2. The home button is the breadcrumb**, drawn in the accent colour so it is noticed; the cover is a picture only and the series name is a plain label, never a link. (Shy: "the series name is *not* a breadcrumb. The home button is."; 2026-11-07 05:41Z: "the cover doesn't need to be clickable any longer if we have a home button. The home button should be colored so it's noticable.")
- **D3. No Files tab either.** Files are reached through the item dropdown; a folder button at the end of the list browses the file structure. File facts move to Quick facts. (Shy, question 1.)
- **D4. Supporting files appear outside the editor too**: on the details page row and in Search. (Shy, question 2 = A.)
- **D5. Fields are locked by default**; unlock one to edit it; a changed value is kept on provider refresh. The lock and Quick facts use the accent colour. (Shy, question 3 and bug 19.)
- **D6. The header cover is about 96 × 144 with no kind label** (bug 20a).
- **D7. Series are read-only canonical groupings; a Universe allows overrides only** (bug 23).
- **D8. No "Change placement"; matching an item moves it** (bug 24). "Line up files" survives as "Match all files in this season / album".
- **D9. Background is a gradient from the cover's dominant colours**, never banner artwork. Uses the colours the Engine already stores with each picture.
- **D10. Footer wording:** "File write-back off — Edits save in Tuvima. Original files stay unchanged."
- **D11. Supporting files are editable items** with title, description, group, role, scope and an optional related episode or lesson; scope inferred from the folder with an override; virtual grouping independent of disk; fields and tabs adapt to the item; movies hide Season and Episode.
- **D12. Match opens on the current match by ID; search only when the user types** (bug 25).
- **D23. Match has two independent sides, Media providers and Wikidata** (Shy, 2026-11-07, match brief and three mocks): compact search → results → selection → apply; fields by kind with pre-fill from file name, embedded metadata and folder hints; TV is show first then a text episode list; music is release then disc and track with a membership preview; local videos, courses and supporting files match only where a provider supports it; local evidence shown beside the result with Strong / Possible / Check verdicts, measured durations distinct from rounded runtimes, missing evidence treated as unknown; Apply always allowed; existing matches show Open source, Change match, Remove match; provider and Wikidata matches independent with a conflict flag; applying updates unlocked fields, keeps locks, writes History, follows file-management settings and overrides folder hints on later scans. **Deliberate overrides of built work:** the v4 batch line-up table (WP8) and the v4.1 "Check the Wikidata link again" switch go; no "connected show" panel, no source-information section, no extra confirmation. The mocks' TMDB for TV is representative; TV stays TheTVDB (v4 D8).
- **D13. One data kind, one name: "Extras" (Shy, answer 1).** Supporting files and Extras are the same records (today's Extras, extended). By default every such file simply falls into Extras; a file in a season or section folder is shown with that season or section (the inference rule, 3b). The editor and the browser say "Supporting files" for the records; the details-page row is "Extras" everywhere, never "Materials". Library has no "course" type: a person **makes** a course by editing (groups they name, roles, titles, "Shown alongside", video order), and a plugin could automate that later (follow-up, not in this spec).
- **D14. Recommendation: "Belongs to" and "Shown alongside" are two different things.** Belongs to is the owner (visibility, delete, where it is listed; inferred from the folder). Shown alongside is a cross-reference to one episode or lesson, for a file that belongs to a season or the whole course. Hidden when the file already belongs to an episode. Reason: a season guide can sit with episode 3 without becoming episode 3's file.
- **D15. Recommendation: thresholds.** 8 inline files per scope in the dropdown; 12 cards per group on the details page; 25 rows a page in the browser. Reason: the dropdown must stay a dropdown; a page row must stay a row.
- **D16. Only what Library can show becomes a supporting file (Shy, answer 2).** Documents (PDF, EPUB, text), pictures, video and audio clips. Hidden, never items: archives (zip, 7z, rar), `.nfo`, `.xml`, `.json` and other metadata sidecars, subtitle files (`.srt`, `.sub`, `.ass`, which belong to the media file), poster, fanart and thumb pictures named for a media file, and anything else Library cannot open. The list stays in configuration (today's Extras rule file), not in code. The browser's Folders and files view still lists hidden files greyed as "Not shown in the library", so nothing is invisible. Reason: documents and media are what matter; a zip or an `.nfo` as a card is clutter, and a sidecar mistaken for an extra would be wrong twice.
- **D17. Recommendation: a picture folder stays one item** ("Concept art · 24 pictures", opening as a gallery), as Extras D11; a lone picture is its own item. Reason: 400 production stills must not become 400 rows.
- **D18. "Suggest details from the document"** (Shy, answer 7: local only) reads the file's own metadata (PDF title, subject, author; first lines of text) on the user's machine, with no provider and no AI. Reason: Privacy; it works offline and never guesses wildly. No AI button.
- **D19. Video order is edited in the item dropdown (Shy, answer 4; detail proposed here).** On a Videos series the item dropdown ends its Videos list with a **Reorder videos** row. It turns the list into an ordered list: drag handles, Move up and Move down on each row (keyboard too), Done returns to the normal list; the Section dropdown reorders sections the same way. The new order is staged like any edit and committed by Save changes, where Review offers v3.1's "rename files to match" as before. The browser's Videos view shows the same order with the same handles, for a course of hundreds of videos. The row never appears on a show, album, comic or book series: their order comes from the match and is not editable. Reason: the dropdown is where the person already sees the order, so the fix happens where the problem is seen; one order model, two views, no new "root view".
- **D20. Recommendation: a scope override and a group survive rescans**; a file that disappears from disk keeps its record for 30 days as "File missing" (today's rule) so a renamed file can be re-linked by the Engine's fingerprint.
- **D22. Look: this spec consumes shared tokens, it defines none** (Look v3 planning thread, 2026-11-07, pending Shy). Dropdowns and menus use `--tl-bg-surface-elevated` (#2F3039), `--tl-border-default`, neutral hover, selected row `--tl-accent-primary-soft` with `--tl-accent-primary-hover` text; no purple surfaces or borders except the selected or primary state. Form sections are groups of rows with hairlines (`AppSettingsGroup` / `AppSettingRow`), cards only for objects (the match card, Quick facts as the one accent card). Icon buttons are the one `AppIconButton` (Outlined, Plain over artwork, Filled). Type: 24/700 title, 20/600 section, 16/500 controls and rows, 14 body, 13 helper. Tooltips only on icon-only controls, disabled-with-reason or truncated text. The mockups' purple dropdown border on the open item dropdown is the selected state; the build uses the token names above, and any missing token is asked of the Look v3 thread. The header gradient from the cover's colours stays this spec's own.
- **D24. Series have no artwork of their own (Shy, answer 3).** A Series (a show's seasons, a book sequence, an album's tracks) is a nesting of real items and takes no shelf picture: its editor has no Artwork tab, and its tiles show the members' own covers. Stacked artwork belongs only to the curated **collection** container, as today. Follow-up outside this spec: the stacked look was designed for square tiles and needs a revisit now the app uses portrait and landscape tiles (noted for the Tiles/Look owners).
- **D25. The View editor inherits the v5 frame (Shy, answer 5, "it does need to actually work").** Photos, videos, documents and galleries (spec photos-documents-editor, Built) move onto v5: landscape picture in the header, the gallery as the family (home button, item dropdown of the gallery's pictures with thumbnails, "All photos" into the picker), tabs Details and History for an item (Details, Artwork, History for a gallery), file facts in Quick facts, the same locks, Galleries chips staged as before. Screen L. Built as WP14 with its own Local check so it is proven on real photos, not assumed.
- **D26. Inline threshold is 8 (Shy, answer 6).** Everything beyond the eight falls into the picker ("All supporting files", screen E), which is also the editor for several at once.
- **D27. Apply match stages; Save changes commits (Shy, answer 8).** No instant write; Review lists "Match changed" with the move, if any.
- **D28. The line-up table is gone for good (Shy, answer 9: "the app should be built to be *easy*").** No "Match the rest of this season" either; the header makes the next file one click away.
- **D29. Delete is always called "Delete" and means the item in the header (Shy, 2026-11-07 05:48Z).** On an episode it deletes the episode; after the home button, on the show, it deletes the whole show with every season and episode; on a season, that season. The button never changes its label ("Delete Show", "Delete episode" do not exist); the one confirmation says what will go and how much: "Delete The Last Signal? Its 2 seasons, 24 episodes and 238 supporting files will be removed from the Library." Files on disk follow the library's file-management setting, as v4 D13. Reason: one word in one place, and the confirmation carries the context, not the button.
- **D30. Belongs to moves the file in a Managed folder (Shy, 2026-11-07 05:51Z).** No Override button: the Belongs to dropdown is the override, with a hint saying whether the value came from the folder or from you and a "Use folder location" link to go back. In a Managed folder, saving a changed Belongs to moves the file into the matching folder (show root, `Season 02`, or the episode's folder) and the footer turns amber with the from → to path first, as a changed match does. In a Read-only folder nothing moves; the file's place in the Library changes and the hint says "Set by you · file stays where it is". Shown alongside and Group never move anything. Reason: one rule for every structural change (match, placement, scope): Managed folders follow the Library, Read-only folders are never touched.
- **D31. "Shown alongside" shows in three places (Shy, 2026-11-07 05:54Z).** (1) A chip under the episode's or lesson's row on the show or course page ("Worksheet · PDF") that opens the file. (2) The episode's or lesson's own Extras row, as a second listing of the same record. (3) On a **course only**, the player's end card gains a "Homework for this lesson" block under Up next (screen M): the file's badge, title, role and size, and Open, which stops the countdown, minimises the player to its bar and opens the document in the reader over the course page. It appears on the last lesson too. Autoplay is unchanged; Dismiss keeps the card with the homework reachable. A show's end card is untouched; nothing ever appears during playback.
- **D32. One browser frame for the supporting-files picker and the folder picker (Shy, 2026-11-07 05:57Z).** Today's server folder picker (used when adding a library folder, a View folder, an import folder and in Tools) is a dialog with a path bar, a Locations list on the left, a toolbar (back, up, refresh, search) and a folder list. The supporting-files picker (screen E) has the same bones: a dialog, a list on the left (Where, Groups), a toolbar with search, a list on the right, a footer. They become **one shared browser frame** (screens E and N) with two row kinds: folder rows (name, modified; click opens, folders only). **One change to the Locked folder-picker plan (Shy, 2026-11-07 06:12Z):** there is no path box: the folder you are inside is the selection, named on the line above the list, and the friendly name is the only text box; "Type a path…" is a row in the Locations list that opens a small box for what a list cannot reach (a network share, a hidden folder, a deep tree), and Go lists that folder. ## 3b. How a supporting file is placed (the inference rule)

Order of checks, first match wins; every result is a proposal the person can override.

1. **Owner (Belongs to).** The deepest title folder the file sits in: an episode's own folder (or a file whose base name equals an episode file's base name, with a suffix such as `-notes`, `-worksheet`, `.pdf`), else a season or section folder, else the show, course, movie, album or book folder. Folder names `Extras`, `Featurettes`, `Bonus`, `Documents`, `Materials`, `Resources` do not change the owner; they are role hints.
2. **Shown alongside.** For a file owned by a section or the whole course: the lesson whose leading number (01, 02…) or whose title words the file name shares. For a file owned by a season: the episode whose code (S02E03) or title words the file name shares. Otherwise none.
3. **Role.** From the type, then the folder and file names: `trailer` → Trailer; `featurette`, `making of`, `behind` → Featurette or Behind the scenes; `deleted` → Deleted scene; `interview` → Interview; `workbook`, `exercise`, `homework`, `worksheet` → Worksheet; `guide`, `handbook`, `manual` → Guide; `transcript`, `subtitle` (text) → Transcript; `notes` → Notes; `booklet`, `liner` → Booklet; a picture folder → Pictures; otherwise Other.
4. **Group.** From a named subfolder under the title's Extras, Documents or Materials folder whose name is not a role word (`Extras/Character guides/…` → group "Character guides"); otherwise none. When a title has more than 12 supporting files and no groups, the details page groups by role family (Documents, Videos, Pictures) until the person names groups.
5. **Title.** The file name without extension, cleaned (separators to spaces, leading numbers kept), until "Suggest details" or the person sets one.

**The naming scheme is public and supported natively (Shy, 2026-11-07 05:48Z).** The folder and file-name words above are a documented scheme, kept in configuration (the Extras rule file) so the words can grow without code, and published as a page in the public docs ("Naming supporting files": one table of folder names and file-name words per role, with examples such as `Season 02/Documents/S02E03 - homework.pdf` and `Extras/Trailers/teaser.mkv`), so a library laid out that way is picked up with no editing at all. The same page says that nothing is lost if a name does not fit: the file still appears, as Other, and can be edited. (WP2 for the rule file, WP12 for the page.)

The two folder kinds in Shy's question (a matched show with a few files, a course with files in every lesson folder) go through the same five checks; the course simply gets more hits at steps 1 and 2.

## 3c. Matching in detail

Shy's direction of 2026-11-07 (three match mocks and a brief). Layout is always **search → results → selection → apply**, compact, inside the Match tab, with the header navigation above it unchanged.

**The tab's first row.** The provider dropdown on the left and a two-way switch, **Media providers** · **Wikidata**, on the right of the same row (Shy, 2026-11-07 06:00Z: no vertical space spent on it); choosing Wikidata removes the provider dropdown and the row holds the Wikidata search instead. Each side has the same shape: an existing match (if any), or a search.

**Existing match (either side).** A card: picture (providers) or text (Wikidata), title, year, kind, creator, the source's name, **Open source ↗**, **Change match**, **Remove match**. Below it **Why this match**: a table of Field · Your file · Matched record · verdict, one row per fact the Engine compared (title, year, episode number, runtime, author, ISBN, and so on), with a note under a fact when it is approximate ("Runtime consistent"). The current match stays until a replacement is applied. The line under the table says: "Changing the match updates unlocked metadata. Locked fields stay unchanged."

**Search (Media providers).**
- **Provider dropdown:** one list, the default provider for this kind first, each entry with its state (Ready, Needs a key, Off). Changing the provider changes the fields. Providers are those configured in `config/providers/` for the item's kind; TV stays TheTVDB only (v4 D8); a provider's logo is its letter badge until a plugin supplies one.
- **Fields by kind:** Movie: Title, Year, provider ID. TV: Show, Year (then the episode list). Book: Title, Author, ISBN. Comic: Series, Issue, Year. Audiobook: Title, Author or Narrator. Music: Artist, Album, Song. The original file name sits under the heading as muted text; the fields are pre-filled with clean values from the file name (noise stripped as v4.1 D5), embedded tags (ID3, EPUB, PDF, MKV title) and folder hints (a show folder, a "Season 02" folder, an artist/album folder, an ISBN in a file name). Everything pre-filled is editable.
- **Results:** rows with picture, title, year, creator and length where known; the selected row is highlighted; a preview card on the right shows the selected result's picture, kind, year, creator, description and Open source.
- **Local evidence** beside the verdict: the title and number read from the file name, the **measured** duration (from the media file), and identifiers found (YouTube ID, ISBN, ISRC, embedded title). Provider runtimes are **rounded**, so the comparison says "1:47:52 measured · 108 min (rounded)" and judges them consistent within two minutes.
- **Verdict:** **Strong match** (every compared fact agrees), **Possible match** (title or number agrees, something else differs or is unknown), **Check match** (a compared fact disagrees), each with its reasons as ticks and crosses. A fact with no local evidence is **not checked**, never counted against the match. **Apply match is always enabled**, including for a Check match; the verdict is advice.
- **Work, edition or release:** for books, comics and audiobooks the result list shows works; picking one shows its editions or releases (year, publisher, format, language) when the provider has them, with the closest to the file's facts suggested. For movies, the release is the provider's single record.

**TV, step by step.** 1) Show search (as above). 2) The matched show card: poster, title, year, genre, seasons, and **Change show**. Change show works whatever folder the file is in; the fix moves the file in a Managed folder (v4.1 D6, amber footer). 3) **Choose an episode:** a Season dropdown and a plain text list of that season's episodes: number, title, air date, runtime. The episode read from the file name (or, failing that, the one whose runtime and air order fit) is pre-selected with "Suggested from filename: S02E03". 4) Verdict and Apply. Specials are Season 0 in the dropdown; absolute numbering (anime) is accepted in the file-name reading and shown as the provider's season and episode.

**Music, step by step.** 1) Search with artist, album or song hints (from tags first, file and folder names second). 2) Results are albums or releases (artist, year, label, format, country) with the release that matches the file's track count and durations suggested. 3) Discs and tracks of the chosen release, with the track whose number, title and measured duration fit pre-selected. 4) If the chosen track belongs to a different album than the song's current one, a **preview** says what changes: "Moves from *Album A* track 4 to *Album B* disc 1 track 7; the song's album, artist and cover follow." Recordings carry their MusicBrainz disambiguation (original, remaster, live, edit, radio edit) in the row so the right one can be told apart. 5) Apply.

**Local videos, courses and supporting files.** A Videos item offers YouTube when a video ID is known (file name or `.info.json`) and nothing else; a course, a section and a supporting file show "No provider matches this kind of item. The details you enter stand on their own." with no search. Manual metadata is always valid without a match.

**Wikidata.** A search box ("Search Wikidata") and a second box "Paste a Wikidata link or QID". Results are **text only**: label, description, entity type (film, television episode, written work, musical album, human), QID, and one distinguishing fact (year, creator, series). The selected result shows **alignment evidence**: the identifiers both sides know (IMDb, TheTVDB, ISBN, MusicBrainz), title, year, creator, each with a tick, cross or "not checked". Direct item and parent are told apart: for an episode the list marks a series result as "Parent: the show, not this episode", and such a result cannot be applied as the episode's identity; the parent is shown as context only. Apply, then the same existing-match card with Open source, Change match, Remove match.

**Independence and conflicts.** The provider match and the Wikidata identity are stored separately and changed separately. After either changes, the tab compares them (shared identifiers, year, title) and shows one amber line when they disagree: "Your Wikidata item is a 2011 film; the TMDB match is from 2023. Check which is right." It never changes the other side on its own. The v4.1 "Check the Wikidata link again" switch on Review goes away; the automatic alignment that today follows a retail match still runs for items that have **no** Wikidata identity yet, and never replaces one you set.

**Applying.** Apply match stages the change in the editor's session (nothing is written until Save changes; Review lists it as one row, as every change does; there is no extra confirmation inside Match). On Save: unlocked fields take the matched record's values; locked fields keep yours; History records "Matched to … (was …)"; the file moves and is renamed only in a Managed folder, with the amber footer before Save; the match is **pinned** (explicit) so future scans never re-identify the file from its folder or name, and a rescan that finds the folder hint disagreeing keeps your match and says nothing.

**Removed, deliberately:** the batch line-up table (v4 WP8, built; Shy 2026-11-07: "Avoid batch alignment tables"), the "connected show" panel, source-information sections, Change placement, the placement picker, and the Wikidata switch on Review. One file at a time, from the header.

## Plain English summary

The editor becomes a window that looks like the thing you are editing: a big cover, the show's name as a label, the episode's title, and under it a home button, a Season dropdown and an episode list with pictures. There is no Contents tab and no Files tab any more; you get around from the header, and a folder button at the end of the list opens the real folders when you need them. Every field starts locked, you unlock the one you want to change, and what you change stays yours when the provider refreshes. The header's colour comes from the cover itself, and the footer tells you plainly that edits stay in Tuvima and your files are untouched.

The guides, worksheets and clips that sit beside your shows and courses become real items: you can name them, describe them, put them in groups you invent, say which season or lesson they belong to, and find them on the show page and in Search. The Engine guesses where each file belongs from its folder and name, and you can correct it. When a show has two hundred such files, a browser with search, filters and bulk editing keeps it manageable; when it has three, nothing changes and they just show up. Match opens on what the item is already matched to and only searches when you type, which fixes the "Nothing called …" bug, and Series become read-only groupings. Every question is answered; it waits only for the word to lock.
