# Home media cards: approved implementation contracts

Architecture owner: GPT-6.1 Sol, Extra High. Implementation workers: GPT-6.1 Sol, Medium. Baseline: `86abe012`; accepted scope: `home-cross-media-cards-plan-2026-09-28.md`. Architecture freeze completed before implementation dispatch on 3 October 2026.

## Product walkthrough and acceptance

1. Home presents a readable, shorter feature, then Continue Across Media and filterable Recently Added, followed by the existing populated media and collection rows. Detail heroes retain their existing height. This maps to H/M; desktop initial views must reveal the first shelf.
2. An untouched show uses show art and its start action. A started show keeps its show title and identifies the selected owned episode beneath it, uses its still and synopsis, and offers the appropriate episode action. Continue and episode details identify the same owned work. This maps to D/C/T; completion advances only to another owned episode.
3. Mixed cards retain landscape episode/movie art, portrait book/comic art, square album art, and an audiobook's measured cover shape. Only partial long-form items receive a progress strip. One card opens one detail surface. This maps to C/T; geometry and accessible status remain stable with pointer, keyboard, and touch.
4. Recently Added mixes permitted catalogue entries with the active profile's Mine View entries by addition time. View files remain View files and open the native viewer. Filters and later pages preserve that scope and do not repeat or skip tied entries. This maps to R/M; an inaccessible second profile and Shared Library never leak into this feed.
5. Phones use a content-sized hero, accessible edge controls, horizontal shelves, safe-area clearance, and readable state without hover. This maps to H/C/M/V; the complete accepted desktop/mobile/stress matrix, including 1920×1080 and 200% text, is required.

The Engine reserves one available representative each for TV, Movie, Read (Book/Comic), Album, and Audiobook, then fills absent buckets from the remaining ranked identities. A TV representative prefers the most recently saved started show, with existing catalogue rank as the fallback; other buckets retain their ranked priority. This makes cross-media coverage visible inside the existing five-slide carousel contract. Alternate TV acceptance cases use actual disposable saved state rather than injected UI candidates.
- A started Home TV spotlight has `Title = ShowTitle`, `Subtitle = Sx Ey · EpisodeTitle`, episode synopsis, show identity in `EpisodeContext`, exact owned episode playback IDs, episode still as background, and root-show backdrop fallback. - If every owned episode is complete, retain the shared resolver's first-owned rewatch target and offer `Restart Episode` with `restart=true`. Home still identifies that exact completed episode, uses its synopsis/still with show-backdrop fallback, and opens its show-scoped episode details. It has Completed state and no resume strip. ## State, security, ordering, and images

- Change `LoadJourneyAsync` to accept the requested `Guid? profileId` and lane. All callers/endpoints pass the claim-derived active profile. Null or mismatched profile fails closed. SQL constrains profile before reading; the authorization wrapper also applies current profile/library grants.
- Add a separate profile-scoped all-state projection (`LoadStatesAsync`) for progress overlays and TV selection. It includes complete states; untouched owned episodes are supplied by the authorized owned-work projection. Continue still contains only genuinely partial long-form items, plus the existing active-album journey. Use `TvEpisodeContextResolver`, completion threshold 99.5, and distinct owned work IDs. Provider-only episodes never become candidates.
- Do not cache per-profile journey/state reads: synchronous bounded SQLite reads always reflect committed progress and avoid stale user state. Existing catalogue projection caches must not capture profile progress. New recent feeds also avoid shared caches, ensuring additions and current authorization are read for each request. No legacy overloads, schema migrations, repair jobs, or compatibility readers are added.
- The Dashboard uses one circuit-scoped internal committed-progress notification carrying profile and asset identity. Direct progress writes and player heartbeats publish only after an acknowledged response for the captured/current profile; transport changes alone do not publish. Home and recent feeds subscribe with disposal and request-version guards. Late responses cannot refresh a newly selected profile or update its progress revision map. Subscriber failures cannot change an acknowledged write into a failed save.
- All new SQLite work uses synchronous Dapper commands after cancellation checks; internal IDs are 16-byte GUID blobs through existing handlers. Keep external IDs/JSON GUID strings as established.
- Saved timing comes from the actual `Dictionary<string,string>` persistence form used by player progress, with invariant finite numeric parsing. Numeric JSON values may also be read, but string values cannot disappear merely because SQLite reports JSON type `text`. Invalid/missing timing remains absent; invalid text must not be coerced to zero.
- Catalogue recent display identities are distinct owned top-level work/show/album identities, using their latest owned addition timestamp. Query/merge both authorized sources by `AddedAt DESC`, then source-qualified `Key` ordinal ascending. Use the last emitted tuple as the sole global boundary. Cursor encodes version, type, profile, timestamp, and key; filter/profile mismatch is invalid. Each source applies that boundary; source-heavy pages and ties cannot skip buffered items. The View query path is `IViewQueryOrchestrator` with Mine and added-at sorting; never join View tables to catalogue SQL.
- The recent Web adapter mints `ViewMediaGrantService` thumbnail/preview grants for the current profile at render/load time and opens the established View immersive viewer. Refresh grants when reloading; never persist them in Engine DTOs/caches. An unavailable View permission contributes no View items to All and a truthful unavailable/empty View scope.
- Shared image helpers select bounded renditions and truthful sizes/srcset. Movie/episode cards use landscape only when that source exists; missing landscape preserves the actual available cover ratio. Audiobooks use measured cover shape. Cover-derived book/album atmosphere reuses hero primitives. View thumbnails use measured ratio and bounded thumbnail/preview grants. No artwork positioning metadata or generated artwork.
- Existing artwork renditions are bounded by longest edge (320/960/2160 pixels) and never upscale. Width descriptors therefore use `round(sourceWidth * min(1, bound / max(sourceWidth, sourceHeight)))`, not the bound itself. Duplicate widths are collapsed; unprovable width descriptors are omitted. Existing display artwork dimensions flow through UI-only Home hero metadata/parameters into the shared backdrop, without new wire fields. The disposable art generator follows the same bounds. Bounded `src` and rendered desktop/mobile/high-density geometry remain required.
- Shared artwork-edge progress/status component consumes explicit state, percent, and label; partial strips carry progress semantics, complete status uses text/check and no resume strip, unstarted has no strip. Albums/tracks/View omit completion semantics. Sequence items gain the corresponding nullable progress/timing/status fields and retain existing `ProgressState`; season totals count distinct owned episodes only.
