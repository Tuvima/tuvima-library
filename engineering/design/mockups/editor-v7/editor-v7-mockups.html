Editor v7 mockups

What changes after the bug review of 2026-11-14: one header on every tab, a Match tab that shows just the match, square pictures, an Artwork tab that fits without scrolling and applies at once, a tidy Review changes step, and no "Saved" box. Each screen shows what the app will show. The numbered dots are not part of the app; they point to the notes under each screen.

What did not change: the v6 screens for TV episodes, songs, Wikidata, the Details rows and the series chooser stay as drawn in editor-v6/editor-v6-mockups.html, except that they now sit under the same full header drawn here. The older drawings in editor-details-revision/ (Match & Identity cards with a header "Not matched" chip, the "Why 96%" panel) were already replaced by v6 and stay as history.

Covers are colored placeholders. Provider marks are letter badges here.

A. Match tab, item not matched yet

Desktop, 1280 wide. The same header as the Details tab. (Issue 991.)

  1. 1The header is the Details header. Same cover, title, facts, Home and item list, on every tab. It no longer shrinks on Match.
  2. 2No "Matched" tag. The facts line has no match word. The top right is the only match signal.
  3. 3Not matched is a quiet line where the links would be. It carries no button and no color.
  4. 4Media providers and Wikidata stay a two-way selector, now at the top of the tab body, not in the header.
  5. 5The rest is v6. One search row, Your file, results on the left, the chosen result on the right. In the real window the list and card scroll inside the body; the header and footer stay put.
  6. 6Apply match has no explanation line under it any more (issue 992). The basis note and the "Links this book to…" line are gone.

B. Match tab, item already matched

Desktop. A movie matched to TMDB. (Issues 991, 992.)

  1. 1The links are the match indicator. TMDB and Wikidata, plain text and one small arrow. A link means matched to that source.
  2. 2Just the match: cover, title, year, key facts and a short description. No "Strong match", no table of agreement, no "Based on…", no "shown from what Library saved", no provider code name.
  3. 3Only two actions, at opposite ends of the row. Remove match on the left, Change match on the right. Open source is gone because the header link does it.
  4. 4Change match opens the search row, Your file and results of screen A. The verdict (Strong, Possible, Weak) shows only there, in the results.

C. Finding a match for an audiobook

Desktop. Results keep their own shape. (Issue 993.)

  1. 1Square pictures in the list and the card, because an audiobook cover is square. Books, movies and shows stay portrait; episodes stay wide; albums and songs stay square.
  2. 2The shape follows the kind of item, and a provider that says its picture is square wins over the default. A square picture is never cropped or stretched.
  3. 3Narrated by is the extra fact for audiobooks in the card. The provider name stays a product name, "Apple Books", never a code name.

D. The header's top right, every state

Only the top-right of the header is drawn. Same on every tab. (Issue 991.)

  1. 1Matched to both: TMDB and Wikidata links.
  2. 2Matched, only one has a page: only that link. A source with no page shows nothing at all.
  3. 3Not matched: the words "Not matched", nothing else.
  4. 4Plain link buttons. The source's name and one small outward arrow, outlined, 32 px tall. No letter badge, no dark pill, no second icon.

E. Artwork tab: everything fits

Desktop, 1280 wide, window about 700 high. Nothing scrolls. (Issues 989, 990.)

  1. 1The same header, with the same match links.
  2. 2A small preview at the role's real shape (here 200 × 300 for a cover), enough to judge a picture. Zoom steps are gone.
  3. 3View full size opens the picture large over the window, for anyone who wants it.
  4. 4Picking a picture applies it at once. Choose, upload, From URL, From Library and Make preferred all change the item the moment you do it. Nothing waits for Save changes. Earlier pictures stay in the versions row, so going back is picking again; there is no Undo.
  5. 5Versions are small thumbnails in one wrapping row. The current one has the purple outline.
  6. 6The footer is unchanged, and Save changes stays off because no data has changed. Discard does not touch pictures.

F. Review changes

Desktop. Shown after Save changes is pressed. (Issue 994.)

  1. 1One line per change: field, old value struck through, new value. The same fact is merged into one line, never repeated.
  2. 2No pictures here. Artwork already applied (screen E), so Review lists data only.
  3. 3One place for files. If a save moves or renames a file, a single amber block says from and to. It does not appear otherwise.
  4. 4One footer row. Back to editing on the left, Discard and Save changes on the right. On a phone they stack in the usual order (screen H).

G. After Save: the item shows "Updating"

The window has closed. A details page header (top) and a tile (bottom left, and the failed case bottom right). (Issue 995, option B.)

  1. 1No box, no step list. The "Saved 1 change" ribbon, its five ticks and its close button are gone.
  2. 2The item shows the app's normal Updating state, the same one it shows while being ingested. It clears when the Engine is done. (The chip here is a stand-in; the build reuses the existing one.)
  3. 3If a step fails, the item shows the app's normal warning, and its History says which step. Nothing else appears when all is well.
  4. 4"See what changed" is the editor's History tab, as it always was. The ribbon link is gone with the ribbon.

H. The same changes on a phone

360 wide. The phone header is one line on every tab, now with only cover and name. Left to right: Match matched, Artwork, Review changes.

  1. 1The phone header is just the cover and the name. No state word and no links (Shy's call). The links sit at the foot of the match card on the Match tab, or "Not matched" there.
  2. 2Remove match and Change match sit side by side with a full gap, each 44 px high, under the match.
  3. 3Artwork: two small previews per row, the chosen one outlined. Tapping a picture applies it at once. "View full size" opens it large.
  4. 4Review changes is the full-screen step with the same compact lines.
  5. 5Footer stacks in the usual phone order: Save changes first, then Discard, then Back to editing.
