# File synchronization capability audit

## Product walkthrough

1. After saving a reviewed editor change, the library identity remains correct even if a physical file cannot be updated. The file outcome must say whether the attempted value was verified, is pending, was blocked by policy, is unsupported, or failed. **W2, W6.**
2. A supported file writer checks the specific fields it can read back after writing. MP3, FLAC, OGG Vorbis, M4A/M4B, MP4, EPUB, and CBZ now have bounded verified field sets; EPUB also checks a referenced cover image. Other attempted fields remain visibly unverified. **W6.**
3. A later clean scan may restore only the identifiers, ordering, facts, and artwork proven to round-trip from that format. Provider confirmation and the full provider catalogue are not reconstructed from a file tag. **W1, W6, W7.**

Acceptance requires a disposable sample of each format, a write, a fresh read through the ingestion reader, and preservation checks for unrelated streams, chapters, attachments, and archive entries. The table below is an audit of current code, not that acceptance proof.

The current `config/writeback-fields.json` is a request list, not proof of adapter support. Each metadata tagger supplies a versioned capability record, and `WriteBackService` rejects present configured values that the selected adapter cannot accept before touching the file. In particular, `TV.season_number` and `TV.episode_number` have MP4 Apple atom mapping, but they do not yet have verified read-back; MKV cannot receive them through the current adapter. MP3 ID3v2, FLAC/OGG Vorbis Xiph, M4A/M4B Apple audio, MP4 video, EPUB OPF standard fields, and CBZ ComicInfo standard fields may receive a verified `ok` hash only when every requested present field passes the respective fresh read-back check inside the backup scope. Audio adapter v5, video adapter v3, EPUB adapter v3, and CBZ adapter v3 delimit this behavior for the retag sweep. All other formats and requests containing unproven fields record an `unverified` marker for the attempted configuration/adapter version. Unsupported requests have their own state, and the retag sweep advances by asset cursor so the same attempted version does not spin in one pass. Broader cross-format field read-back and a desired-state fingerprint are still missing. The artwork service has its own `ArtworkEnabled` gate; EPUB cover byte/reference verification in its tagger does not by itself establish the production artwork service's status reporting. The UI must not present unverified metadata writes as confirmed physical changes.

## Required implementation decisions and evidence

1. Expand the implemented per-adapter write preflight into a full read/write/remove and artwork-role capability contract. Validate the JSON field list against it and prove container-specific behavior with fixtures.
2. Expand the minimal disposable MP3, FLAC, OGG Vorbis, M4A/M4B, MP4, EPUB, and CBZ read-back fixtures with unrelated metadata, chapters, streams, archive entries, and attachments for broader preservation assertions; add M4V, MKV, and other OGG codecs.
3. Add a versioned Tuvima identifier envelope with explicit provider, entity type, and Work/Edition/Asset or show/season/episode/release-track/recording scope. Read historical tags and flag contradictory IDs.
4. Extend the proven MP3, FLAC, OGG Vorbis, M4A/M4B, MP4, EPUB, and CBZ field subsets to other supported fields, formats, and artwork roles. Report a field or role as Verified only when a fresh reader returns the desired value, with backup restoration on mismatch. Stamp the applied fingerprint only then.
5. Coordinate metadata and artwork under one per-file lock, recheck file and desired-state fingerprints immediately before mutation, and feed verified self-writes to watcher state.
6. Evaluate a Matroska writer with packaging, platform, licensing, attachment preservation, and disposable-file round-trip evidence before adding a new native dependency.

No new sidecar fallback is enabled by this audit. Existing configured export behavior remains separate.

## Plain-English completion summary

The audit identifies which file changes the current adapters attempt and where they can prove the result. MP3, FLAC, OGG Vorbis, M4A/M4B, MP4, EPUB, and CBZ now verify only the specific metadata fields listed above; EPUB also verifies a referenced cover image's bytes. A mismatch restores the backup. Other fields and formats remain visibly unverified. Format-wide synchronization, broad preservation of unrelated media data, and offline restoration are still acceptance work.
