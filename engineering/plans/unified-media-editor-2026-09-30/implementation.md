# Unified media editor implementation ledger

## Product walkthrough

1. **Keep one highlighted target.** The header names the selected Work, Edition, or Asset; adjacent selectors provide parent and sibling context. Details, Artwork, Match & Identity, and History follow that target, while ordinary browse, playback, and detail routes remain unchanged. **W1, W2, W4.**
2. **Navigate without a persistent file browser.** Scope selectors and searchable popovers replace the earlier file checklist concept. Selecting an item updates the header and every editor section; there is no selection count or batch Save/Discard surface. **W1, W2, W4.**
3. **Persist artwork at the declared owner.** A show poster, season poster, episode still, album cover, or supported edition cover retains its owner. Tile selection, import, and confirmed unlink persist immediately in the editor. Inheritance and affected-file status remain separate from the artwork choice. **W1, W5, W6.**
4. **Apply only supported identity corrections.** Same-owner and reviewed same-show TV corrections use server evidence and revision checks. One selected music file can move to an exact MusicBrainz release Track ID after a bound review; siblings stay in place. Cross-show moves and other unverified owner changes remain blocked. **W2, W3, W7.**
5. **Report physical-file outcomes truthfully.** Supported write-back uses durable work, format capability checks, backup, and read-back. The UI distinguishes verified, pending, policy-blocked, unsupported, and failed results. Later ingestion recovers only facts actually written to a supported file. **W1, W6, W7.**

Observable acceptance includes a single Asset; several Assets for one Work; several meaningful Editions for one Work; several Assets in one Edition; a TV episode with two versions; original and deluxe music releases; and one ambiguous multi-episode file left in review. Each case shows one active target. Desktop, tablet, and mobile layouts keep selectors and actions aligned without overlap. An exact reviewed release-track move changes only the chosen music file; ambiguous or conflicting moves leave its identity unchanged.

The walkthrough maps directly to W1–W7 below.

The supplied screens are visual references for density, readable hierarchy, and artwork tile treatment. They do not authorize a persistent file checklist, batch controls, a fixed parent header, or a second artwork dashboard. The current interaction uses one selected-item header, adjacent context selectors, and one owner/role gallery with one clearly preferred image.

## Scope and input authority

The attached editor handoff is the current implementation specification. Earlier editor plans and edition notes provide background. Its screenshots are layout and content examples: sample titles, counts, and match states are not fixture evidence. This ledger tracks code and verification; it does not turn the attachment into a separate user request.

### Target ownership matrix

| Media | Structural owner | Work owner | Edition or release owner | Asset owner | Default artwork owner |
| --- | --- | --- | --- | --- | --- |
| Movie | optional series | film identity and provider movie ID | supported cut/release distinction | file path and measured technical facts | film Work, optional Edition override |
| TV | show and season | episode identity/number | optional version | file and technical facts | show poster/background/logo, season poster, episode still |
| Music | release-group context | recording and release-track context | exact MusicBrainz release | audio file | exact release when actually modeled; current album Work otherwise |
| Book | optional series | literary identity and series order | ISBN, publisher, translation, edition date | ebook file | Edition |
| Audiobook | optional series | literary identity | narration/release, ASIN, cover | part file and embedded chapter structure | Edition |
| Comic | run/volume | issue identity | optional printing/variant | comic file | issue, optional Edition override |

The current database does **not** yet realize every target cell. In particular, a per-file technical Edition is not an exact music release. The read model reports current effective ownership, while any ownership migration needs a separate data repair and acceptance test.

## Decision and risk ledger

1. **Model availability:** The worker tool in this Codex session does not offer Terra. Available workers are assigned disjoint files under Sol orchestration; model substitution is reported to the user.
2. **Frozen selection boundary:** The all-matching endpoint returns explicit IDs and revisions up to 1,000; the Match UI preserves them, and preview requires complete revisions. New files do not join a reviewed operation, and the existing blanket batch mutation endpoint is not used for parent-first matching.
3. **No client-authored identity commit:** Episode title/number, release, and parent links must be verified by the Engine against provider or established local evidence before the database transaction. The TV HTTP Save now accepts only an actor-bound review token, accepted provider episode IDs, exclusions, and an operation token; catalog-only targets are rechecked for zero actual assets in the transaction.
4. **Writer capability:** Existing `.mkv` handling cannot be promoted to complete scoped Matroska write support without a writer spike and independent file read-back. Unsupported and unavailable are separate outcomes.
5. **Data repair:** Existing wrong asset/work claims and per-file technical Editions require an auditable dry-run before bulk migration; future-only routing changes cannot repair them.
6. **Cross-show correction:** The current verified TV transaction encodes one show and checks source and target under that show. A cross-show Save needs a dual-show operation that recalculates ownership for both roots and their seasons, rechecks both shows' artwork impact, and authorizes every target owner and library. The existing guard rejects such a move without mutation; its focused negative test passes. Preview may show a different show, but it is read-only until this transaction exists.
7. **Exact music release-track identity:** The selected-file relocation now freezes a provider release manifest and requires its exact Track MBID. It does not infer placement from a Recording MBID, disc/track text, or an album Work hint. Ambiguous legacy Editions, occupied destinations, and active identity work fail without mutation. Broader migration of release-scoped Edition claims and bridges remains separate work.
