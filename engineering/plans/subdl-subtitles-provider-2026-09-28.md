# SubDL subtitle provider replacement plan

Status: implemented in the working tree on 28 September 2026, pending a live keyed SubDL search/download and visual Settings check before release. No SubDL credential has been installed by this change.

## Plain-English product walkthrough

1. **Connect SubDL once in Settings.** An administrator opens Providers, follows a link to create or sign in to a SubDL account, generates a personal API key in the account's API section, enters it in Tuvima, and uses **Verify & connect**. Tuvima reports whether the key works and, where available, the account's remaining searches and downloads. An unconnected installation still uses embedded and local subtitle files. Maps to packages A and D.
2. **Movies get subtitles for the matched movie.** A movie with a confirmed TMDB match searches SubDL by that movie's TMDB ID and type. Language, release name, hearing-impaired preference, and file compatibility decide which result to use. If a result is uncertain, Tuvima leaves the current track alone and offers review instead of silently choosing a likely wrong subtitle. Maps to packages B and C.
3. **TV subtitles follow the owned episode, even when catalogs number it differently.** TheTVDB remains the episode identity source. Tuvima verifies the show's TheTVDB/TMDB ID pair, then asks TMDB to find the owned episode by its TheTVDB episode ID. If TMDB returns an episode belonging to that same show, Tuvima uses TMDB's season and episode numbers for SubDL. For example, if TheTVDB calls an episode S2 E1 while TMDB calls the same episode S1 E13, the subtitle search uses the verified TMDB coordinates. If TMDB has no direct link, Tuvima reviews other evidence and stops automatic download unless the match is unambiguous. Maps to packages B and C.
4. **Existing subtitles stay playable.** Replacing the provider does not remove files already downloaded from OpenSubtitles, imported sidecars, embedded tracks, user-selected preferred tracks, or playback progress. New online searches use SubDL after the cutover. Maps to packages C and D.
5. **Provider choices become simpler.** OpenSubtitles disappears from new setup and active lookup. Fanart.tv disappears from setup if the final inventory confirms it has no active adapter. Existing artwork and its source label remain visible. TMDB and TheTVDB keep their established metadata and artwork roles; LRCLIB keeps lyrics. Maps to package D.

**Observable acceptance:** an administrator can connect a SubDL key without giving Tuvima a SubDL password; a matched movie and a same-number TV episode acquire a playable, correctly labeled track; a differently numbered TV episode searches using the verified TMDB episode position; an ambiguous episode acquires nothing automatically; previously selected subtitles continue to play after OpenSubtitles is retired. Settings clearly distinguishes a bad key, exhausted quota, provider outage, and no matching subtitle.

## Current implementation and provider facts

- The Engine currently registers `OpenSubtitlesTextTrackProvider` through `ITextTrackProvider`. `TextTrackEnrichmentWorker` imports local sidecars first, preserves user-owned preferred tracks, then searches online providers and stores normalized WebVTT per owned asset. The current OpenSubtitles adapter searches by IMDb or title plus season/episode, downloads the first file of each candidate, and does not use TMDB IDs despite advertising them in its configuration. Its result ranking uses limited release evidence. See `src/MediaEngine.Api/DependencyInjection/TuvimaProviderServiceCollectionExtensions.cs`, `src/MediaEngine.Providers/Providers/OpenSubtitlesTextTrackProvider.cs`, and `src/MediaEngine.Providers/Workers/TextTrackEnrichmentWorker.cs`.
- This checkout already has a TheTVDB v4 client and metadata provider, `tvdb_id` / `tvdb_episode_id` bridges, a TMDB show bridge, and selectable TVDB episode orders in its client. The earlier `tvdb-tv-editor-ordering` plan's statement that no TVDB client exists is stale. The current metadata adapter still resolves generic TV episodes by TheTVDB season/episode numbers in its default order. This subtitle plan must not assume that every owned episode has an approved cross-provider episode mapping.
- `TextTrackEnrichmentWorker.BuildLookupAsync` currently flattens asset, episode, and parent bridge records by key and takes the first value. Package B must replace that with explicit movie, show, and episode scope so a parent `tmdb_id` can never be mistaken for an episode ID, nor can a child ID be used as the show ID. `BridgeIdKeys.TmdbId` is show-scoped for TV and `BridgeIdKeys.TmdbEpisodeId` is episode-scoped.
- SubDL's current [v2 developer documentation](https://subdl.com/developers) supports bearer or `X-API-Key` authentication, `GET /api/v2/subtitles/search` by TMDB ID with mandatory `type=movie|tv`, TV season/episode filters, `unpack=1`, downloads, and `GET /api/v2/me` for a non-billable account/quota check. Use v2 as the target contract. The older [v1 documentation](https://subdl.com/api-doc) remains useful for interpreting archive fields but is not the target integration. Verify real v2 response and download fixtures with a test account before finalizing DTOs; the public page gives fewer subtitle response details than the v1 page.
- SubDL's [current terms](https://subdl.com/terms) permit users to bring their own API keys and prohibit pooling them or using one free shared key to power a commercial service. The documented [v2 limits](https://subdl.com/developers#errors) are currently 2,000 searches and 50 downloads per day on Free, and 30,000 searches and 2,000 downloads per day on Pro. Treat those as provider-controlled values and show `/me` counters or rate-limit headers rather than hardcoding limits. Confirm SubDL's applicable caching rules before retaining remote search responses for the current seven-day provider cache TTL.
- TMDB already exposes a show-level `tvdb_id` in this repo's TV ingestion path. Its [series external IDs endpoint](https://developer.themoviedb.org/reference/tv-series-external-ids) validates that pair. Crucially, TMDB's [`/find/{external_id}` endpoint](https://developer.themoviedb.org/reference/find-by-id) supports TheTVDB IDs for **TV episodes** as well as shows; its [episode external IDs endpoint](https://developer.themoviedb.org/reference/tv-episode-external-ids) can verify the reverse link. TheTVDB's [v4 API](https://thetvdb.github.io/v4-api/) provides stable episode IDs. These direct links are the first-choice crosswalk, but the current repo does not yet use them for subtitle lookup.
- Fanart.tv has no current provider JSON or active adapter. Remaining code references are legacy artwork provenance labels and source filters; its ignored secret file is local credential material. `fanart.jpg` is the local background-artwork filename produced and moved by Tuvima's sidecar handling; it does not call or depend on Fanart.tv and must remain supported.

## Technical work packages

### A. SubDL account, onboarding, and provider contract (walkthrough 1, 5)

- Register a new immutable `WellKnownProviders.Subdl` ID and provider row; add `config/providers/subdl.json`, icon, capability metadata, rate limit, status/help links, and Settings onboarding. The account steps are: create/sign in at [SubDL](https://subdl.com/), open the account panel's API section via [Get an API key](https://subdl.com/developers), generate a key, copy it into Tuvima, verify, and save. Offer optional Pro information without making a paid plan a prerequisite. Use one administrator-supplied key for a single personal installation; if Tuvima later becomes a multiuser commercial service, review per-user key ownership before release under SubDL's terms.
- Store the key only in the Engine's existing ignored provider secret mechanism, `config/secrets/subdl.json`, through `ProviderCredentialService`; never put it in source, a browser response, a URL, or a log. Use the v2 bearer header for search, `/me`, and download calls. Ensure credential rotation or removal immediately invalidates cached access and that failed validation does not save a bad key. No SubDL username or password fields.
- Make `GET /api/v2/me` the non-mutating credential probe and parse its success body; extend the generic probe only where its current header configuration and path handling are insufficient. Report invalid key, quota exhausted with reset time, rate limit, unavailable service, and connectivity separately. Add a host-allowlisted, bounded HTTP client and provider rate-limiter integration. Do not use Pro AI translation, transcription, uploads, or AI filename search in this migration.
- Confirm the v2 response fields, single-file and archive download behavior, allowed formats, redirects, error shape, and quota headers against sanitized account fixtures. Pin the API version in tests. Treat return values and links as untrusted; use provider-owned HTTPS hosts only, constrain archive size and entry count, reject traversal and ambiguous multi-file packs, and avoid echoing the key in failures.

### B. Typed movie and TV identity for subtitle lookup (walkthrough 2, 3)

- Replace the flattened `BridgeIds` guesswork with a typed subtitle lookup context: asset/file identity and release filename; movie TMDB/IMDb IDs; TV show TheTVDB and TMDB IDs; owned TheTVDB episode ID and selected order; verified TMDB episode ID and TMDB season/episode position; language preference. Read each value from its proper lineage scope and record its evidence/provenance. Keep subtitle provider data out of catalog identity, canonical claims, and Wikidata matching.
- For movies, require the confirmed movie TMDB ID when available, send `tmdb_id` plus `type=movie`, and verify the returned title identity. Use IMDb only when it is the confirmed movie ID and TMDB is unavailable. A text or filename result can supply candidates for user review but must not automatically change the matched media identity.
- For TV, first validate a one-to-one show link using the existing paired bridge IDs and TMDB's show `tvdb_id` external ID, or TMDB `/find/{tvdbShowId}?external_source=tvdb_id` when the TMDB show ID is missing. Cache the relationship with source and freshness; reject conflicting or multiple show matches. Then call TMDB `/find/{tvdbEpisodeId}?external_source=tvdb_id` and inspect its TV-episode results. Accept exactly one result whose `show_id` matches the verified TMDB show; verify its episode external `tvdb_id` where available. Save its TMDB episode ID plus **TMDB** season and episode coordinates as scoped crosswalk evidence, without overwriting local or TheTVDB placement. If that direct link is absent, compare the correct TheTVDB order's episode with TMDB episodes using original air date, specific title, duration, and season context; auto-accept only a unique, strongly corroborated result and send every other case to review. Exact season/episode numbers alone are insufficient. Revalidate after a show/order change or provider rematch.
- Search SubDL with the verified TMDB show ID, `type=tv`, and **TMDB** season and episode numbers. Check the returned series identity and each candidate's episode/range or unpacked file coordinates. Specials, absolute order, DVD order, double episodes, missing air dates, same-day episodes, translated or duplicate titles, and show splits require explicit handling; unresolved cases route to a review/no-result state. No lookup may use TheTVDB coordinates as a silent TMDB substitute.
- If the current TVDB editor/ingestion code cannot provide a durable verified episode crosswalk, implement that shared identity contract first or keep these episodes manual-only. This package aligns with the existing TV episode-order work; it does not redesign the editor or renumber library files.

### C. Candidate choice, download, and playback continuity (walkthrough 2–4)

- Add `SubdlTextTrackProvider` behind `ITextTrackProvider` and reuse `TextTrackEnrichmentWorker`, `SubtitleNormalizer`, `TextTrackRepository`, playback endpoints, and preferred sidecar export. Search by confirmed ID first. Normalize SubDL language codes to Tuvima's canonical language tags and request only configured languages. Use release filename as compatibility evidence **after** identity and episode validation, not as authority to rematch a work. Rank exact release/episode, normal versus forced, hearing-impaired preference, format, framerate if known, and source evidence. Do not infer confidence merely from popularity or a provider-generated match score.
- Accept a single explicit subtitle file or a pack entry proven to be the target episode. Verify archive entry path, format, byte size, decompression ratio, language, and episode before WebVTT conversion. If format is unsupported or multiple entries remain plausible, do not auto-select. Preserve provider source ID/URL as historical attribution, but do not persist signed/credentialed URLs or API keys. Make repeat downloads idempotent per asset, provider subtitle ID, file ID, and language.
- Preserve local, embedded, manually imported, and previously downloaded OpenSubtitles tracks, including the chosen preferred track. New SubDL results must not automatically replace a user-owned preferred track. Keep the existing local-only/manual metadata policy and owned-asset boundary. No provider calls for View personal media, unowned catalog episodes, books, music, or lyrics.
- Improve worker outcomes so missing key, unsupported media, ambiguous match, no subtitle, incompatible pack, quota, provider error, and successful import are observable without treating an empty result or cancellation as a provider failure. Bound retries/backoff to rate-limit headers; avoid a batch consuming the daily quota through repeated searches for the same confirmed identity and language.

### D. Deprecation, migration, documentation, and verification (walkthrough 1, 4, 5)

- Add SubDL to provider catalog, schema seed, health/activity labels, first-run and Settings tests, and any generated reference/help surfaces. Remove OpenSubtitles from active provider JSON, DI registration, onboarding, setup copy, icon, test assumptions, and current architecture/tutorial/reference text. Keep its well-known ID or an explicit retired-provider record and historical source labels so existing text tracks, audit rows, and backups still resolve. Do not delete old normalized tracks, source attribution, or user choices. After migration, remove the unused adapter and obsolete credential login/token code. Stop loading old secrets; offer an administrator-facing reminder to revoke the old key and remove the ignored local file after successful cutover.
- Confirm the Fanart.tv inventory remains empty in active provider discovery, artwork download, and runtime configuration. Remove stale setup/credential guidance and unused local secret convention. Retain historical `fanart_tv` source display names and artwork picker filters while old assets may exist; retain `fanart.jpg` local sidecars. Do not delete old artwork or silently relabel its provenance.
- Update `docs/plans/tvdb-tv-editor-ordering-2026-09-28.md` or supersede its stale status statement as part of implementation, and align provider strategy, onboarding, pipeline, privacy, attributions, and operating documentation with TheTVDB for TV identity, TMDB for movies/show crosswalk and SubDL matching, SubDL for optional subtitles, and LRCLIB for lyrics.
- Add focused contract tests with recorded, scrubbed v2 responses; movie ID and exact episode cases; TVDB/TMDB number divergence; missing/conflicting show or episode links; specials and packs; key rotation, quota/429, unavailable service, malicious archives, and no-result responses. Add a migration test proving OpenSubtitles tracks remain playable and preferred. Run the provider/API/Web suites and solution build, then verify one movie, one ordinary TV episode, one divergent-order episode, one ambiguous episode, and Settings at desktop/mobile sizes. A live SubDL smoke test should be opt-in and use a user's key without recording it.

## Delivery order and worker model

The **architecture lead and final integrator use `gpt-6-astra` with high reasoning**. This work has one cross-provider identity decision, a source-scope data change, and a migration boundary that need a single accountable reviewer. **Implementation workers use `gpt-6-sol` with high reasoning** for packages A, C, and D; package B's episode crosswalk should use `gpt-6-astra` with high reasoning because an incorrect result can attach subtitles to the wrong owned episode. Use `gpt-6-luna` only for bounded documentation or reference sweeps after contracts are stable, with review by the integrator. These assignments follow [official OpenAI model guidance](https://developers.openai.com/api/docs/models) and its [Codex coding guidance](https://developers.openai.com/api/docs/guides/code-generation); they are task recommendations, not a claim that workers have been launched.

1. The architecture lead fixes the typed lookup, crosswalk evidence, SubDL v2 DTO, provider ID, and file ownership contracts before parallel coding. Record those decisions in the implementing PR so workers do not invent incompatible keys or scopes.
2. Worker A owns provider catalog, credentials, probe, and HTTP client. Worker B owns show/episode crosswalk and typed lookup. Worker C owns SubDL search/download/normalization and worker selection. Worker D owns retirement inventory, docs, and test updates. Shared domain contracts are assigned to the architecture lead; workers do not edit them independently.
3. Merge B before C because C relies on verified episode coordinates. Merge A and B independently after contract review, then C, then D. The integrator rebases each branch against the merged state, runs focused tests at every merge, resolves API/config/test conflicts, and performs one full solution build plus end-to-end acceptance check. Deliver one coherent PR and one plain-English product summary. Do not mark the cutover complete until all packages and the migration gate pass.

## Scope boundaries and release gate

This plan covers download/search replacement, not SubDL uploads, AI translation, a hosted key proxy, bulk subtitle replacement, or a new TV catalog UI. SubDL is optional. Existing media, personal edits, and local subtitle access stay usable when SubDL is disconnected or offline.

Release only when account setup works with a user-supplied key; the typed lookup never confuses movie, show, and episode IDs; divergent TheTVDB/TMDB episode numbering is handled through verified mapping or explicit review; old OpenSubtitles tracks remain accessible; Fanart.tv has no active setup path but historic artwork still displays; quota/error states are recoverable; and all cited documentation reflects the shipped behavior.

## Plain-English completion summary

The plan replaces new online subtitle searches with SubDL while keeping existing subtitle files and user choices. It uses TMDB matches for movies and a verified TheTVDB-to-TMDB episode link for TV, so differently numbered episodes do not receive the wrong subtitle. It also removes obsolete provider setup paths and gives one architecture lead responsibility for merging and checking the complete change.
