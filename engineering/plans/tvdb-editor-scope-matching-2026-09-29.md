# Multi-level media matching plan

> Superseded by [Editor matching by the identity being edited](./editor-hierarchical-matching-default-order-2026-09-29.md). This file records the earlier alternate-order proposal; the current product path uses TheTVDB's default order.

Status: revised 29 September 2026. This plan covers editor targets with parent and child identities. The editor, matching API, and hierarchy changes described as implemented below are in this checkout; the remaining stages are called out separately. Live TheTVDB use requires a configured provider credential.

## Plain-English product walkthrough

1. **Choose which identity to correct.** From a child item, the editor offers clearly named actions for its applicable levels: TV Series / Season / Episode; Music Album / Track; Comic Run / Issue; Book or Audiobook Series / Work. A movie's film-series grouping is shown separately from the movie match when a trusted provider container exists. Matching the current parent changes that parent's identity for all its children. **Move this item to another parent** changes only the selected child. Maps to packages A and C.
2. **Compare like with like.** A parent lookup searches parent records and compares parent title/year/creator to parent facts. The opened child title appears only as context. Thus Solo Leveling is compared to a series, an album to an album, and a comic run to a run, while episode, song, and issue titles are used only for their child lookups. Provider IDs and candidate types stay visible. Maps to packages A and B.
3. **Match intermediate and child identities.** For TV, match the owned season under the confirmed show/order, then choose the exact episode. For music, match the album release or release group at album scope, then the recording/track at song scope. For comics, choose the correct run/volume before the issue. Book and audiobook series and their owned works follow the same level distinction where the provider has a genuine series record. Ambiguous titles require manual choice. Maps to packages B and C.
4. **Correct a misplaced child without relabeling siblings.** If one song belongs to a different album, select **Move this track to another album**, review the destination album and track position, and confirm. The old album's other songs and identity are untouched. The same child-scoped move applies to a misgrouped episode, comic issue, book, or audiobook where that hierarchy is supported. Matching the current album/show/run is a different action with a different impact preview. Maps to packages A and C.
5. **Choose an order where the provider offers one.** A TV show can use available aired, DVD, absolute, or named TheTVDB orders. Switching order previews affected season/episode links and requires confirmation. Comic runs use their real issue positions; book and audiobook series keep source ordinals. These are provider sequence facts, not universal numeric offsets. Maps to packages B and D.
6. **Handle an emptied parent later and safely.** Moving the final song may leave an album with no owned tracks. The move completes without deleting that album or its artwork in the same transaction. The editor shows the empty source as a cleanup candidate; a separate orphan cleanup process can remove only unreferenced, non-curated parent records and unused artwork after checking every owned link and override. The same rule covers other empty structural parents. Maps to packages C and D.
7. **Keep ownership and artwork dependable.** Provider catalogs do not create owned media. Existing files, playback progress, personal edits, and preferred artwork remain intact. Artwork refresh uses the confirmed identity at the same level; a missing image stays missing. Cross-provider number equality alone is not an identity link. Maps to packages C and D.

Owned-only detail lists, media files, playback actions, and single-level matches stay the same. This plan does not add a hosted metadata proxy, import unowned provider items, bulk-renumber libraries, or delete empty albums during a move.

**Representative TV journey:** Open an owned Solo Leveling episode titled “Are You the King of Humans.” Match the series to TheTVDB's Solo Leveling, then the owned Season 2 to TheTVDB Season 2, then the file's exact episode. Each comparison uses the title and ID of the level being matched.

**Representative music journey:** Open a song grouped under the wrong album. Choose **Move this track to another album**, select the destination release, and review the recording/track association. The old album keeps its remaining songs. If this was its last song, its empty record and artwork await separate verified cleanup. Choosing **Match album** instead would correct the identity of the whole existing album, so the editor must explain that wider effect before applying it.

**Representative comic journey:** Open an issue assigned to the wrong run. Select a Comic Vine volume/run and confirm only this issue's membership, then match the exact issue within that run. A same-title run from another year or publisher must remain a separate candidate.

**Observable acceptance:** parent candidates never compare against child titles or receive a “best match” badge from child-title similarity. Applying a parent identity updates the parent record, not a child ID. Season 2 appears when present in the chosen order; episode selection stays within its confirmed show/order. A track move changes only that track's album membership, preserves siblings and files, and leaves an empty source album available for later cleanup. Comic issues and book/audiobook works follow the same scope rule where their provider supports a distinct parent. Reopening the editor shows the correct IDs and membership at each level.

## Findings that drove this plan

The following bullets describe the behavior at the start of this review. The first implementation pass below has already corrected several of them.

- The Series scope uses the `show` target. `TvdbMetadataProvider.SearchAsync` returns **series** records when no season number reaches it. `BuildRetailSearchFields` strips local S/E for a show lookup without a query override; the editor normally supplies its prefilled query as an override, so the provider also receives no structured S/E. The Solo Leveling result can therefore be a genuine series result.
- The displayed comparison is wrong for that scope. `BuildDraftFields` starts with the opened media detail. `BuildRetailComparisonRows` takes `title` before `show_name`, and the search endpoint ranks retail candidates using `context.WorkTitle` plus all episode file hints. Thus “Are You the King of Humans” is compared with “Solo Leveling,” giving a misleading low title score and total confidence. The screenshot does **not** by itself show that an episode ID was saved as the series.
- On apply, the `show` policy is a container policy; `ResolvePolicyIdentityTarget` routes it to `WorkLineage.TargetForParentScope`, which is the root show for TV. `IsTvdbShowCandidate` checks submitted bridge IDs but does not re-fetch the selected series to prove its type server-side. `TargetScopeId` is not the primary identity-target selector.
- Separate `/tvdb-match/season` and `/tvdb-match/episode` endpoints already exist and require a root `tvdb_id`. They currently use the provider's **default** season order. Season apply stores `tvdb_season_id`; episode apply stores `tvdb_episode_id`. Episode apply verifies show membership, but does not require consistency with a previously matched season ID. The picker has no per-show order setting or placement preview.
- The existing series-search test covers the no-override field filter, not the prefilled-query and score path visible in the screenshot. There is no complete show → season → episode confirmation test.
- The same generic editor search/comparison path serves Music album/track and Books, Audiobooks, and Comics series/leaf scopes. Its title-first comparison can score an album or run against the currently opened song or issue. Music has explicit album and track policies; Books/Audiobooks/Comics have series policies, but the current Web target list falls back to the leaf option for some series scopes. The editor must derive allowed targets from the active scope rather than a media-wide default list.
- `HierarchyAlignmentService` already has transactional child reparenting for TV, Music, Comics, Books, Audiobooks, and movie series. It updates the selected leaf's parent and ordinal while retaining editions/assets. A focused regression test confirms that moving an album's final track leaves the former album and artwork in place. Empty-parent cleanup is separate maintenance, so no eager deletion belongs in the rematch transaction.

## Provider API mechanics and level mapping

| Library hierarchy | Provider identities to keep distinct | Search and selection boundary |
| --- | --- | --- |
| TV show → season → episode | TheTVDB series, season, episode IDs plus a show-level order | Series search returns shows; seasons and episodes are fetched within the confirmed show and selected order. |
| Music album → track | MusicBrainz release group/release and recording/track IDs; Apple album/track IDs where available | An album candidate corrects the album identity. Reassigning one song chooses a destination album/release and then verifies its recording/track association. A recording may appear on several releases; recording identity alone cannot pick an album. |
| Comic run/volume → issue | Comic Vine volume and issue IDs | Choose the particular run using its ID, year, publisher, and issue span, then select an issue within that run; equal series titles alone do not merge runs. |
| Book/audiobook series → owned work | Proven series/container identity and work/edition/provider IDs | Offer parent matching only when a provider returns an actual series identity. A local or Wikidata series relationship is not an edition ID; changing one work's membership must not relabel siblings. Embedded audiobook chapters are source-authored tracks, not independent retail works. |
| Movie series → movie | Trusted film-series membership and movie ID | Keep group placement separate from the movie's own match; offer provider selection only where the catalog exposes a stable group ID. |

[MusicBrainz's API](https://musicbrainz.org/doc/MusicBrainz_API/Search) has separate recording, release, and release-group search indexes, which is why song identity and album placement are separate decisions. [Open Library's book API](https://openlibrary.org/dev/docs/api/books) distinguishes works and editions; it does not by itself establish every claimed book-series membership. The Comic Vine run/issue distinction is already represented by separate volume and issue bridges in Tuvima's provider code.

Artist, author, narrator, and cast/person matches are contributor relationships. They may have their own identity picker, but choosing one does not move a song, book, or episode between structural parents. Embedded audiobook chapters, loose playlists, and curated collections likewise do not receive a provider parent/child picker unless a real provider identity and membership relationship exists.

### TheTVDB detail

| Scope | API path | Required rule |
| --- | --- | --- |
| Series | `GET /search?query=...&type=series`, followed by `GET /series/{id}/extended` and translation | Keep the candidate typed as a series through search, comparison, and apply; verify its ID on apply. |
| Season | Series extended data contains season IDs, numbers, and types; `GET /seasons/{id}/extended` resolves one season | Filter by the selected order and verify that the selected season belongs to the confirmed show/order. |
| Episode | `GET /series/{id}/episodes/{seasonType}/{language}?page=N` returns an order-specific, paged list; `GET /episodes/{id}/extended` resolves one episode | Page to completion and verify show, order, and matched-season membership. Use local S/E and title as search evidence, not identity. |
| Alternate orders | The series declares a default season type and may have named types | Show only available orders. Recut orders can contain **different episode records**, so a global number offset or assumption that IDs persist is unsafe. |

These mechanics are documented in [TheTVDB's v4 API guide](https://github.com/thetvdb/v4-api/blob/main/README.md) and [API specification](https://github.com/thetvdb/v4-api/blob/main/docs/swagger.yml). The guide specifically warns that episodes may be absent from some season types and that recuts can use distinct episode records. Tuvima's client already calls these paths. It uses an installation-supplied key; deployment still needs authorized [API access and attribution](https://thetvdb.com/api-information).

## Technical work packages

**Implemented in this checkout:** The editor selects match targets and comparison labels from its active TV, Music, Comic, Book, or Audiobook scope. Parent searches use parent title evidence; Comic Vine run searches return volume IDs; the comic move picker offers local and retail runs. TheTVDB season and episode browsing offers available Default, Official, DVD, and Absolute orders. The season control filters to the chosen provider season, and the controls and result rows have bounded widths and inset padding. A season is verified against the matched show and selected order; an episode requires a confirmed season and is verified against that season, show, and order before apply. Browsing another order requires applying that order to the show before a season or episode can be matched in it. The show has a persisted order preference with an impact preview: applying a change is blocked if already matched season or episode IDs do not fit the requested order. The generic show apply re-fetches the selected TheTVDB series. MusicBrainz track matching verifies that a selected recording belongs to the selected exact release; Comic Vine issue matching requires matching volume evidence when a run is already confirmed. Hierarchy moves reject incompatible parent targets, and moving the last track leaves its old album and artwork intact. The move preview identifies when the source parent will become empty; existing maintenance protects empty parents referenced by profile state or user-selected artwork. Focused API, provider, storage, and editor checks cover these paths.

**Still to deliver:** Ingestion of newly identified, unmatched TV episodes still uses the provider's default order; it needs the root show's confirmed order propagated into provider lookup. TheTVDB custom/named orders are not selectable yet. Non-TV parent matches need provider re-fetch and type verification on apply where the catalog supports it, plus complete provider-backed parent/child selection in the manual picker. Empty-parent cleanup after reparenting remains a separate stage with a dependency audit and its own preview; the current move only announces the empty source. Desktop/mobile visual acceptance review also remains. The packages below describe the full target experience; the current code does not implement every package.

### A. Typed target and operation across the editor (walkthrough 1, 2, 4)

- Make **Series**, **Season**, and **Episode** explicit match targets, including a direct **Match series** action while viewing an episode. Pass a typed target context with target entity ID, scope, parent IDs, order, and scope-specific display fields. Do not infer the target title from the opened file's generic `title`.
- Series searches and confidence use show title/aliases and show premiere year. Exclude episode title, local S/E, and episode date from series ranking. A query override changes search text only; it must not make scoring fall back to episode hints. Label the comparison **Series title** and show the episode title in an “Opened from” context line. Suppress “best match” when scores are for a different scope.
- Keep candidate kind `series` through the API contract and UI. Re-fetch `/series/{id}/extended` on apply, validate the resolved root show and requested scope, and reject an episode ID even when client-supplied bridge fields look plausible. Consider a dedicated TV series apply endpoint so the guarantee does not depend on client-selected `TargetFieldGroup`. Confirmation copy must say the **series** was matched, not “this file.”
- Define the same target contract for Music album versus recording, Comic Vine volume versus issue, and supported book/audiobook series versus work. Build scope-specific queries, file hints, comparison labels, ranking, and provider-ID allowlists. Never use the active child title as the parent title. Verify candidate entity type and parent membership at the server boundary where the provider exposes them.
- Distinguish `Match current parent`, `Match this child`, and `Move this child to another parent` in copy, preview, and request shape. A parent identity correction must not be presented as a one-song move; a child move must not overwrite the old album/run/show identity.

### B. Scoped provider catalogs and sequences (walkthrough 2, 3, 5)

- Build a typed catalog layer over `TvdbRetailClient` returning available order IDs/types/names, seasons, paged episodes, stable IDs, order-specific coordinates, images, language, and freshness. Cache by show + order + language. Avoid a translation request per displayed row when page data suffices.
- Store the chosen order per show, defaulting to the provider's declared order. Use that same key for season and episode pickers and ingestion. Show season 0, missing seasons, loading state, and provider errors explicitly. A missing Season 2 in one order should offer available alternate orders, not an empty unexplained selector.
- Keep local season/episode placement separate from `tvdb_season_id`, `tvdb_episode_id`, and source coordinates. Do not use a universal arithmetic offset. A title-only proposal remains reviewable rather than automatically accepted.
- For Music, expose release group/release/recording or track relationships already returned by the configured provider, with explicit release and recording IDs. A selected recording can be offered on more than one release, so the destination album choice stays explicit. For comics, return volume/run candidates with stable volume IDs, start year, publisher, and candidate issue IDs; filter issue selection within the chosen run. For books and audiobooks, only offer provider series selection when a stable series/container ID is available; preserve source ordinals and edition-level identity separately.
- A common result contract should report candidate `entityKind`, `providerId`, `parentProviderId`, `sourceOrder`, and evidence as applicable. The UI may share layout and state handling while provider-specific catalog adapters enforce valid relationships. If a provider cannot prove a parent/child link, present the item as unresolved for manual review rather than silently creating one.

### C. Parent-child apply, movement, and artwork (walkthrough 1, 3, 4, 6, 7)

- Series apply changes only the root show identity. Season apply verifies the season belongs to that show **and order**, and writes only season identity and season-scoped metadata/artwork. Episode apply verifies membership in the show/order and, when a season is confirmed, in that season; a conflict opens explicit placement review.
- After a series match, offer **Match season** for the selected owned season. After a season match, offer **Match episode** for the selected owned episode. Preselect the confirmed season, then the local season if available; allow deliberate browsing elsewhere. A season match may show likely episode links but does not apply them automatically.
- Keep episode rows left aligned with inset padding, bounded still thumbnails, and clear focus/selection states. Refresh artwork only for the confirmed scope and preserve a user-selected preferred image. A confirmed child ID outranks number/title guesses in both ingestion and manual matching.
- Reuse `HierarchyAlignmentService` for child-scoped movement. Its transaction should update the selected leaf's parent and ordinal together with verified identity fields, retain the leaf's editions/assets, and reject occupied or incompatible destinations. Preview exactly which child and parent are affected. Music needs a clear track→album move; comics issue→run, book/audiobook work→series, and TV episode→season/show should use the same boundary when supported. A movie's series placement uses a separate membership action from movie identity matching.
- Moving the final child leaves its former parent and artwork references intact. Record that empty parent as eligible for a **future** orphan-cleanup pass, but do not delete or transfer its art during rematch. Define later cleanup eligibility by zero owned children **and** no curated membership, manual override, profile reference, or other retained dependency. Empty-parent cleanup implementation is outside this matching change.

### D. Preview, migration, and verification (walkthrough 5–7)

- Before changing order or owned placement, show unchanged IDs, alternate-order candidates, conflicts, unresolved files, affected season links, and artwork effects. Apply only confirmed rows with revision checks. Preserve existing TMDB and TheTVDB ID namespaces; reuse TMDB stills only with verified cross-provider episode evidence.
- Test the screenshot case: opening “Are You the King of Humans” must search, rank, and compare Solo Leveling as a **series** even with the prefilled query. Test wrong-scope IDs, root-show storage, Season 2 and specials, direct season apply, an episode outside the matched season, paged alternate orders with different episode IDs, translated/duplicate titles, provider outage, and preferred artwork. Inspect desktop and mobile editor layouts.
- Add cross-media tests: album candidate compared with album title while launched from a song; moving one of several tracks and then the last track; old album ID/art retention; recording on multiple releases; same-title comic runs from different years/publishers; issue move without sibling changes; book/audiobook series versus work/edition IDs; movie series placement versus movie match. Verify that a parent rematch updates parent identity without moving a child and that a child move leaves the source identity unchanged.
- Roll out the shared target/comparison repair first, then complete provider-specific pickers and preview/apply rules by hierarchy. TheTVDB order switching and eventual empty-container cleanup remain separate stages with their own acceptance tests.

## Plain-English completion summary

The visible TV problem is part of a wider scope issue: a provider result for a parent can be judged against the opened child. The plan makes every supported level explicit, from TV show/season/episode to album/song and comic run/issue, and separates correcting a parent's identity from moving one child. Moving the final song can leave an empty album and its artwork safely in place until a later cleanup process verifies that they are truly unused.
