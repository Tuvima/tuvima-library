# One Engine at a time on a shared machine

Many sessions and their helper agents share Shy's computer. A running Engine (with its Dashboard, background services, ingestion and AI work) takes a large share of the machine's memory and processor, so several at once slow every thread down. The Engine also allows only one copy per Windows sign-in (process lease `TuvimaLibrary.Engine`). Rule (Shy, 2026-10-20):

1. **One running Engine on the machine, across every session and helper.** That includes ingestion baseline runs, record-and-replay runs, visual checks, benchmarks and manual runs. A Dashboard runs only beside that one Engine, never on its own against another session's Engine.
2. **Run one only when nothing else will do.** Prefer tests (in-process Engine hosts, bUnit), page reads of an already-running preview and text checks. Visual checks, baselines and anything tests cannot cover are the reasons to start one.
3. **Claim the slot before starting.** Check that no Engine is running (look for a `MediaEngine.Api` process) and read the shared queue in the **main checkout's** ignored `.tmp/engine-slot.md` (not a worktree's copy). Add yourself to the queue with your session name, what the run is for and how long it should take; take the slot only when you are first and nothing is running. Sessions that hand over by message still update the file.
4. **Keep it short and isolated.** Use a temporary data folder (`TUVIMA_CONFIG_DIR`, `TUVIMA_DATA_DIR`, `TUVIMA_DB_PATH`, and one shared `TUVIMA_DATA_PROTECTION_DIR` for Engine and Dashboard) and ports other than 61495/5016, never Shy's real library or data store. Do the work that doesn't need the Engine first, so the slot is held only for the run itself.
5. **Release it the moment you are done.** Stop your own Engine and Dashboard (the preview stop tool, or `pwsh -File tools/Stop-WorktreeDotnet.ps1` for this checkout's processes; never kill every `dotnet` process), remove yourself from `.tmp/engine-slot.md`, and message whoever is next. Never leave an Engine running while you wait for a reviewer, CI or another turn.
6. **Never work around the lease** (renaming it, a second Windows sign-in, a container, a different machine name) to run a second copy. If the slot is taken, queue and carry on with other work.
7. **Heavy test runs count too.** A full-solution test run starts many in-process Engine hosts. While iterating, run targeted tests; keep full runs for the end of a packet, one per session at a time.
