# Viewer read route inventory (Vault sections spec D32, WP0).
#
# Every GET route the Engine maps that a signed-in person (not only an administrator or a service application) can call, and that does
# not carry a per-resource catalogue check (RequireCatalogue...Access), is listed here with how it keeps the Vault, hidden libraries,
# Selected libraries and the content limit out of its answer. ViewerAccessGuardrailTests fails the build when a mapped route is in
# none of these lists, when a rule here matches no route, and when the file named for a rule has stopped using its mechanism.
#
# Format: <route pattern> | <mechanism> | <file under src/MediaEngine.Api, + joins several> | <why>
# A pattern is an exact route, or a prefix ending in * . The first rule that matches a route decides it.
# Mechanisms (the evidence each one needs in the named file is in ViewerAccessGuardrailTests.Mechanisms):
#   viewer-access-service    asks IViewerAccessService, so people and counts start from the viewer's catalogue
#   display-projection       built from the authorized display projection (or a composer / resource check over it)
#   catalogue-authorization  every file or entity it returns passes CatalogueResourceAuthorizationService or the player scope
#   personal-scope           the signed-in person's own activity or taste, scoped by PersonalScopeAuthorizer
#   view-scope               View: its own index and scopes, never part of the Work/Edition graph; documents-off and personal spaces
#   vault-area               the Vault area: behind the Vault gate, unlocked session only
#   own-data                 the caller's own account, device, session, profile or settings; no catalogue content
#   system                   setup, health and network facts; no media, people, counts or events
#   plugin                   plugin pages and the plugin host; no catalogue content
#   grant                    a signed, short-lived grant minted after the catalogue check of the file it serves
# Remove a line when its route goes. Do not add a line to get a build through: say, in the last column, why the route cannot
# return anything the viewer may not see.

/access/* | own-data | Endpoints/AccountEndpoints.cs | sign-in methods, devices, self-service notices of the signed-in person
/api/v1/activity* | personal-scope | Services/Activity/PersonalActivityReadService.cs | a person's own activity; others only through the scope authorizer
/api/v1/taste | personal-scope | Services/Taste/PersonalTasteService.cs | a person's own taste
/api/v1/collections* | display-projection | Endpoints/CollectionClientEndpoints.cs | native app collection reads over the authorized projection
/api/v1/universe/* | display-projection | Endpoints/CollectionClientEndpoints.cs | universe reads limited to works the viewer may see
/api/v1/companion/context | display-projection | Services/ReadServices/CompanionContextReadService.cs | the companion's context card over the authorized projection
/api/v1/companion/* | own-data | Endpoints/CompanionEndpoints.cs | the paired devices and session of the signed-in person
/api/v1/devices* | own-data | Endpoints/ClientAuthorizationEndpoints.cs | the caller's own paired devices and downloads
/api/v1/display/* | display-projection | Endpoints/DisplayEndpoints.cs | Home, browse, search, shelves and grids composed from the authorized projection
/api/v1/nsfw/status | own-data | Endpoints/VaultEndpoints.cs | whether the caller's own session has Vault mode on
/api/v1/pairing/review/* | own-data | Endpoints/ClientAuthorizationEndpoints.cs | a pairing code the caller is approving
/api/v1/playback/diagnostics | system | Endpoints/PlaybackEndpoints.cs | tool readiness only
/api/v1/playback/encode/jobs | own-data | Endpoints/PlaybackEndpoints.cs | the caller's own device's offline encode jobs
/api/v1/player/* | catalogue-authorization | Endpoints/PlayerEndpoints.cs | player state and capabilities; every queued item passes the player catalogue scope
/api/v1/profile-state/* | display-projection | Endpoints/ProfileStateEndpoints.cs | the profile's own reactions and saved items, narrowed to visible works
/api/v1/progress/* | catalogue-authorization | Endpoints/ProgressEndpoints.cs | the profile's own progress, narrowed by the player catalogue scope
/api/v1/vault/* | vault-area | Endpoints/VaultBrowseEndpoints.cs + Endpoints/VaultImageEndpoints.cs | the Vault area, behind the Vault gate
/api/v1/view/* | view-scope | Endpoints/ViewClientEndpoints.cs | View for native apps, through View scopes
/auth/* | own-data | Endpoints/AuthenticationEndpoints.cs | sign-in state of the caller
/collections* | display-projection | Endpoints/CollectionEndpoints.cs | collections, series and system views over the authorized projection and the viewer's work ids
/entity-editor/universes/* | display-projection | Endpoints/SharedEntityEditorEndpoints.cs | universe pages over the authorized projection and per-entity checks
/library/works | display-projection | Endpoints/LibraryEndpoints.cs | the works the viewer may see
/network/* | system | Endpoints/NetworkEndpoints.cs | network facts of this machine
/persons | viewer-access-service | Endpoints/PersonEndpoints.cs | the people list starts from the viewer's catalogue (leak 2)
/persons/presence | viewer-access-service | Endpoints/PersonEndpoints.cs | presence counts start from the viewer's catalogue (leak 2)
/persons/role-counts | viewer-access-service | Endpoints/PersonEndpoints.cs | role counts start from the viewer's catalogue (leak 2)
# Every other /persons route is checked per person (RequireCatalogueEntityAccess). PersonRoutesAreReviewedOneByOne pins each one, and the
# people a route reaches through a link (aliases, group members) go through the viewer's catalogue as well.
/plugin-host/v1/* | plugin | Endpoints/PluginHostEndpoints.cs | the plugin host's own records

/profiles* | own-data | Endpoints/ProfileEndpoints.cs | profiles of the caller's own household

/settings/* | own-data | Endpoints/UISettingsEndpoints.cs | the caller's own display settings and media types

/system/* | system | Endpoints/SystemEndpoints.cs | health and status
/universes | catalogue-authorization | Endpoints/UniverseGraphEndpoints.cs | universes, each checked by qid and limited to visible works
