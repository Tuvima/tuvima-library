# Home and shared media cards: implementation plan

**Status:** proposed plan, 28 September 2026. This document plans the attached Home/card request; it does not implement it. The three supplied images are visual references, not a source of library content or a replacement for Tuvima's navigation and accessibility rules.

## Product walkthrough

1. **Home starts with a shorter cinematic feature.** The Home hero occupies roughly 60–65% of a normal desktop viewport, subject to a readable minimum and responsive adjustment. Its bottom fades into the library surface, so the first row is visible sooner. Previous and Next sit at opposite hero edges; a wider purple dash marks the active slide. The detail-page hero remains on its existing full-height contract. **Work packages:** H, I.
2. **The feature reflects what the profile is doing.** An untouched TV show uses its show backdrop, title, synopsis, and start action. Once an owned episode is resumable, its Home slide keeps the **show title** and adds `Sx Ey · Episode Title` beneath it, then uses that episode's still, synopsis, remaining time when known, and Resume Episode action. A missing still falls back to the show backdrop. Movies use their own landscape art; books and albums keep their real cover art visible against a softened background made from the same asset. No generated art or focal-point controls are introduced. **Work packages:** D, H, T.
3. **Continue Across Media follows the hero.** One horizontally scrolling row mixes the profile's resumable TV episodes, movies, books, comics, and audiobooks. A recently active album keeps its existing square listening-journey placement and Play/album meaning, without a completion bar; ordinary tracks do not become resumable cards. Artwork stays landscape, portrait, or square as appropriate. Titles and status lines align along a common lower area despite different image shapes. A thin purple progress strip appears only on genuinely resumable items. **Work packages:** D, C, M.
4. **Recently Added comes next.** All, Watch, Read, Listen, and View switch a row ordered by when an item entered the library, with All selected initially and View all opening a complete recent browser with the same selected scope. View entries come from the separately authorized View source; they are never put into catalogue identity or progress storage. Progress appears only when the item itself has real resume state. Existing Watch, Read, Listen, and Collections & Lists rows continue below these two rows when populated. Recently Added replaces the old deduplicated Fresh placement so the same recency shelf does not appear twice. **Work packages:** D, R, M.
5. **TV episode state is visible everywhere it matters.** A show discovery card remains show-oriented until started. A started show's Continue representation identifies the exact owned episode and opens its show-scoped episode detail; the Resume action there starts playback. The same episode artwork, progress treatment, metadata, and truthful synopsis appear in its season array. Untouched episodes have no bar, partial episodes have a bar and resume status, and completed episodes have a watched state. A season can show a small `7 of 10 watched` summary using owned episodes only. **Work packages:** D, C, T.
6. **The same experience works on phones.** The hero stacks content without hiding the action or controls, the mixed rows scroll horizontally, image shapes remain truthful, and the existing mobile navigation remains. Keyboard, touch, focus, screen-reader progress text, and reduced-motion settings work across these states. **Work packages:** C, H, M, V.

**What stays the same:** Home is the only lane with a cinematic landing hero; the established top/mobile navigation, detail surfaces, playback and reading state, catalogue versus View separation, purple design language, and existing downstream shelves remain. Cards stay one semantic link to a detail surface; direct Resume/Read/Play remains a hero or detail action. TV ownership never includes provider-only episodes.

**Representative journeys:** A person discovering an untouched show sees show art and opens its show detail. After watching part of S2 E5, Home shows the episode still and Resume action, while Continue links to S2 E5 detail with the same progress. A reader sees the actual portrait cover in a book hero and a portrait card in Continue. A listener sees square album art without a completion strip. A person selecting View in Recently Added sees only View items they may access; selecting All mixes authorized recent entries without changing how View files are stored.

**Observable acceptance:** At 1536×1024, the first Home shelf is visibly present in the initial viewport, edge arrows and the active purple dash are clear, and the hero remains readable. At 1024×768 and 390×844, controls and actions remain reachable with no horizontal page overflow. A started TV slide changes to the exact resumable owned episode; an untouched show does not. Mixed cards never stretch or crop a book cover into a landscape box. View access is enforced independently. Screen captures for every state in the validation matrix below are reviewed before completion.

## Technical contracts and work packages

**A — architecture contract freeze (GPT-5.6 Sol, high).** Before any Home edits, confirm the exact DTO additions, media shape policy, TV resume target selection, allowed card navigation, recent-feed ordering, and View authorization. Record ownership and tests. `DisplayCardDto`/`DisplayHeroDto` remain the public catalogue display projection; add an explicit subject such as Work/TvShow/TvEpisode/Album and a continuation state plus episode identity/resume context where existing fields cannot carry them safely. Keep ViewAsset in a separate typed recent-item branch. Freeze exact TV hero fields: `Title = show title`, `Subtitle = Sx Ey · episode title`, `Description = episode synopsis`, primary action = Resume Episode to the selected owned episode; missing still falls back to root show backdrop. The Watch landing remains show-art-oriented unless separately changed. Reuse `TvEpisodeContextResolver` for selection. Do not infer a started show from text labels or a nonzero percentage alone. Freeze this contract for the Terra workers.

**D — Engine data and state (GPT-5.6 Terra, bounded worker; depends on A).** In `src/MediaEngine.Api/Services/Display/DisplayJourneyProjectionReader.cs`, `DisplayCardBuilder.cs`, and `DisplayComposerService.cs`, reuse `src/MediaEngine.Domain/Services/TvEpisodeContextResolver.cs` to choose the current partial episode or next owned episode after completion. The current journey query intentionally returns only partial items; add a separate, profile-scoped all-state map for owned episodes (including untouched and complete) rather than changing Continue into a completed-items row. Extend `IDisplayProjectionReadService.LoadJourneyAsync`, SQL, every Home/Browse/Continue/lane caller, the `/display/continue` endpoint's claim-derived profile, and cache keys to carry the active profile. The authorization wrapper already post-filters, but raw reads and caches should be profile-scoped too. Invalidate/version relevant display caches when user progress is written so Home, detail, and Continue update together. Project actual `user_states.extended_properties.position_seconds` and `duration_seconds` when present; format remaining time from those fields, never from guessed canonical runtime. Keep untouched show cards and unstarted show heroes rooted in show art. Compose started Home TV heroes with the frozen A fields and show-backdrop fallback. Deduplicate Home spotlight candidates by root show/work identity so an episode replaces, rather than appears beside, the same show's unstarted slide; the current `BuildSpotlights` title/subtitle comparison is insufficient. Ensure Continue and show-scoped episode detail identify the same work. Add progress percent and accessible status to `SequenceItemViewModel` in `src/MediaEngine.Api/Services/Details/Internals/DetailCompositionOrchestrator.CollectionBuilder.cs`; derive season completion from distinct owned IDs. Keep recently active album placement without a music completion percentage. Tests cover exact target selection, missing still, completion, next owned episode, profile change, cache refresh, spotlight de-duplication, and provider-only episode exclusion.

**C — shared card presentation (GPT-5.6 Terra, bounded worker; depends on A and D contract).** Extend `MediaTile`, `MediaTileShelf`, and the central tile composer/artwork resolver rather than creating Home or detail-specific episode cards. Freeze one long-form state policy for TV episodes, movies, books/comics, and audiobooks: untouched has no strip, partial has the artwork-edge purple strip plus readable percent/remaining status, and completed has a concise Watched/Read/Finished state without a misleading resume strip. Episode number/title/synopsis layer on top of that policy. Albums/tracks and View assets never use completion bars. Use one media-aware shape policy: episode/movie landscape, book/comic portrait, album square, audiobook's truthful cover shape, and View asset's measured ratio. Use `AppProgressBar` or a small shared artwork-edge wrapper with progress semantics and labels. The row aligns caption/status baselines while image frames retain native ratios. Raise Home tile size modestly (about 20–30% from its current compact sizing), then validate actual item count at each viewport. Keep whole-card detail navigation, bounded image renditions, and unchanged grid geometry on focus/hover.

**H — Home hero and carousel (GPT-5.6 Terra, bounded worker; depends on A and the D DTO contract; may run beside C).** Keep the existing hero composition primitives. Apply the 60–65svh target only to the Home landing variant, with content-driven minimum and shorter-height fallback; do not shrink shared detail heroes. Move Previous and Next to the outer usable edges with touch-sized targets and labelled focus. Keep the timeline centered and make the active dash thicker/wider and purple; retain pause, announced position, automatic-rotation pause on focus/hover, and reduced-motion behavior. Use center-cropped landscape art and the existing cover-derived book/album treatment. Add a simple dark fade at the bottom, without decorative dividers or focal-point metadata.

**T — TV detail episodes (GPT-5.6 Terra, bounded worker; depends on D and C).** Feed the same episode state into `SequencePlacementPanel` and any episode-specific preview used by Home/Watch. Show episode title, Sx Ey, runtime/remaining-time when known, and the episode synopsis on hover and keyboard focus; missing data stays absent rather than being invented. Render untouched, partial, and watched states with the shared progress/status treatment. Add a compact owned-only season summary without cluttering the selector. Preserve show-scoped episode routes and the owned-only season array.

**R — Recently Added and View boundary (GPT-5.6 Terra, bounded worker; depends on A; can run beside C/H).** Add `GET /api/v1/display/recent?type=all|watch|read|listen|view&cursor=&limit=` and a typed recent-page DTO with catalogue-card and View-asset branches; omitted `type` means All. Home requests its first bounded page and `/recently-added?type=<selected>` requests later pages through the same contract. Reuse catalogue card DTOs for Watch/Read/Listen. The View branch defaults to the active profile's **Mine** scope only; Shared Library stays in View until the user explicitly chooses that scope there. Query View's existing authorized `IViewQueryOrchestrator` path by asset `CreatedAt` rather than its usual capture-date timeline (extend its sort/cursor contract), then adapt only permitted results with View-native open/viewer behavior. `ViewPage.razor` currently uses `ViewMediaGrantService` to mint short-lived URLs for the active profile and scope: the Web adapter must mint those grants at render time, and Engine DTOs/shared caches must contain only stable asset identity and metadata, never expiring grant URLs. Do not join View tables to catalogue display SQL. For All, keyset-page both authorized sources with one opaque composite cursor ordered by added timestamp then source-qualified identity; merge up to the requested limit and return a cursor at the last emitted item. Ties, source-heavy pages, filter changes, and later pages must neither omit nor repeat items. Add an unboxed All/Watch/Read/Listen/View selector. The public recent route is distinct from Administration's `/settings/recently-added`. Profile-aware caching/invalidation must follow both catalogue additions and authorized View additions. No View ID enters catalogue claims, search attribution, Review Queue, or playback progress. Hide empty source options only if the selected state remains intelligible; do not show unauthorized content.

**M — Home composition and responsive layout (GPT-5.6 Terra, bounded worker; depends on C, H, R).** Render Hero → Continue Across Media → Recently Added → existing populated Watch/Read/Listen/Collections rows, retiring the old Fresh row. Keep the page as a coordinator, with state and projection in the shared services. Use the established rail/mobile-navigation and layout tokens. Ensure a vertical phone hero, horizontal card scrolling, fixed artwork ratio, aligned captions, and no obscured content. Preserve the current empty-library and loading behavior.

**V — focused tests and screenshot evidence (GPT-5.6 Terra for tests; GPT-5.6 Sol, high for integration).** Terra updates API and bUnit component tests around DTO/state behavior, not source-text snapshots alone, and creates a task-owned executable fixture/capture workflow under `scripts/visual-qa/home-media-cards/`. Sol reviews each package against A, reconciles duplication, runs build/tests, and inspects live UI screenshots and interactions. Fix visible errors before integration is declared complete.

Dependencies: `A → D → C/T`, `A → H`, `A → R`, then `C + H + R → M`, then `V`. Worker ownership should minimize shared-file overlap: D owns Engine DTO/projection; C owns `MediaTile`/shared progress; H owns carousel; T owns sequence detail; R owns recent/API/View adapter; M owns Home composition and responsive integration. Have one worker modify `DisplayComposerService` at a time; if D and R both need it, R waits for D or uses a separate composer partial/service agreed in A.

## Multi-model integration workflow

1. The **architecture lead runs on `gpt-5.6-sol` with `high` reasoning** and finishes A before implementation contracts are delegated. This planning pass used that prescribed model. A bounded validation inventory also ran on `gpt-5.6-terra` with `medium` reasoning; neither agent edited code.
2. **Implementation workers run on `gpt-5.6-terra`** with explicitly assigned work packages and the frozen A contract. Separate managed worktrees are used only when parallel changes justify them. Start from a clean commit/ref and leave the unrelated dirty `main` checkout intact. The project instruction to stop running Engine/Web processes applies before development or verification begins.
3. The **integration lead runs on `gpt-5.6-sol` with `high` reasoning**. Review each worker diff, integrate in dependency order, resolve conflicts centrally, and run the full solution build and relevant test suites. Once approved, merge the task's work back to main without overwriting pre-existing TVDB work. A clean task diff is required; do not claim the whole `main` checkout is clean while unrelated changes remain.
4. Retire only task-owned worktrees and scratch output after integration. Keep a compact set of accepted screenshots with the implementation report, remove superseded comparison captures, and report any measurable cleanup. Never remove user media, required app data, unrelated branches, or unknown files merely to satisfy a cleanup line in the attachment.

## Plain-English completion summary

This plan uses the shared hero and card system already in Tuvima, adds one consistent way to show episode and reading progress, moves a shorter Home feature above mixed Continue and Recently Added rows, and keeps View permissions separate. The prescribed Sol and Terra agents completed read-only planning work. Implementation, tests, live screenshots, integration, and cleanup remain future work.
