# TV episode catalog and editor matching plan

Status: proposed, 28 September 2026. The custom TMDB season/episode picker, offset mapping, and title fallback from the previous plan have been backed out of the working tree. No TheTVDB client or access credential has been added.

## Plain-English product walkthrough

1. **The show has one clear episode list.** Match a TV show in its Series scope. When TheTVDB is available, the editor shows that show's real season list from the chosen episode order. A show such as Solo Leveling can show an aired Season 2 with 13 episodes, even though TMDB groups the same continuation under Season 1. The list is provider catalog context; only files in the library count as owned. Maps to packages A and B.
2. **Pick the order that fits the library.** The show has an Episode order setting with the available aired, DVD, absolute, or other supported provider orders. Aired order is the proposed default for a new TheTVDB match. Changing it previews which owned episode matches would change, and asks for explicit confirmation before saving. A user can retain the current order when it already works. The setting applies to TV generally, not to an anime flag. Maps to packages A, B, and D.
3. **Match an owned episode by identity.** In the Episode scope, choose from that show's episode list, with its season, number, title, air date, and still preview. A parsed S/E or absolute number narrows the results; a meaningful title can help find a differently numbered episode. The user sees the exact file and provider episode before confirming. Generic or duplicated names are shown as ambiguous, not silently chosen. A confirmed episode keeps a stable provider episode ID even if display ordering changes later. Maps to packages B and C.
4. **Season matching follows the chosen order.** In Season scope, the editor shows the owned season number alongside the selected provider season and its artwork. Matching a season records the provider season identity; review proposes corresponding owned episode matches and clearly separates exact, uncertain, and conflicting rows. The user may accept only the correct rows. The editor keeps card widths, inset spacing, and left alignment consistent. Maps to packages B and C.
5. **Artwork and local ownership stay dependable.** The show, season, and episode can use artwork from the approved provider and, where an exact cross-provider link is verified, TMDB. A missing image is reported as missing rather than being replaced with artwork from the wrong episode. Existing owned files, personal edits, user-selected artwork, playback state, and owned-only detail lists remain intact. Offline browsing uses already stored metadata and images; matching and refresh need provider connectivity. Maps to packages C and D.
6. **Existing libraries move carefully.** Existing TMDB matches are not mass-renumbered. For each show, a migration preview compares the current TMDB identity, local S/E, any stored `tvdb_id`, and TheTVDB's selected order. Clear links can be confirmed together; conflicts remain for individual review. The editor and ingestion use the same catalog/order rules after migration. Maps to packages A, C, and D.

Observable acceptance for a product owner: with an authorized TheTVDB connection, Solo Leveling's aired order presents owned Season 2 as Season 2 and can match its first file to TheTVDB S2 E1 without renaming or moving that file. A non-anime series with a different DVD order can select that order through the same controls. Changing orders does not invent owned episodes, replace a user-selected still, or silently rematch files. If the provider is unavailable, the existing library remains browsable and the editor reports the connection problem.

## Decision and access findings

- Sonarr is installed locally but calls its hosted **Skyhook** metadata service. A Sonarr maintainer describes Skyhook as “[our TVDB proxy](https://forums.sonarr.tv/t/sonarr-not-updating-episode-list/22745).” This is why Sonarr installations do not need to embed or collect a separate TheTVDB key for routine lookups. It also means fresh metadata lookup is not fully offline; a [Skyhook outage can block new episode discovery](https://github.com/Sonarr/Sonarr/issues/5491).
- TheTVDB's v4 API is **not keyless or open access**. Its [current pricing and attribution page](https://thetvdb.com/api-information) lists a free tier for projects or parent companies below $50k annual revenue, with attribution, and paid tiers above that. [Project-key signup](https://www.thetvdb.com/api-information/signup) requires an account; the [v4 API](https://thetvdb.github.io/v4-api/) uses the key to obtain a bearer token. Tuvima's eligibility and intended distribution model need to be checked before implementation. A self-hosted Tuvima build should not assume that embedding a shared key is acceptable or secret.
- [TheTVDB's Solo Leveling page](https://thetvdb.com/series/solo-leveling) lists aired Season 2 with 13 episodes and an absolute ordering of 25 regular episodes. [TMDB's Solo Leveling series](https://www.themoviedb.org/tv/127532) places the continuation in Season 1. The difference is a catalog/order choice affecting more than anime; title comparison alone cannot repair every series-order disagreement.
- The repository already records a `tvdb_id` show bridge when TMDB supplies one, but currently has a TMDB provider/client and no TheTVDB client or provider configuration. That bridge can aid show linking, but does not establish episode-to-episode identity across providers.

**Recommendation:** make episode order a first-class, provider-neutral TV concept. Add TheTVDB as a supported catalog if access is approved, using aired order as the initial suggestion where it fits. Keep TMDB available for existing series identity and artwork, with explicit provider IDs and verified crosswalks. Do not replace every TV record with TVDB numbering in place. Do not build a Sonarr/Skyhook-style hosted proxy merely to avoid a key until the project's hosting, licensing, and support model warrants it.

## Technical work packages

### A. Provider access and order model (walkthrough 1, 2, 6)

- Confirm project licensing tier, attribution placement, permitted deployment model, and whether Tuvima uses its own licensed project key or a user-supported key/PIN model. Register/configure access through provider settings and encrypted credential storage. The Engine owns token exchange, caching, refresh, retries, and bounded requests; the Dashboard never receives a provider secret. Missing or invalid credentials fail closed with a recoverable error.
- Add a TV episode-order contract keyed by show provider ID and order ID/type. Preserve separate local season/episode placement and provider season/episode position. Store TheTVDB show, season, and episode IDs as distinct bridges beside TMDB IDs; never overwrite one provider's ID with another's. TheTVDB v4 exposes series episodes by season type, and its series record describes a default order ([v4 API repository](https://github.com/thetvdb/v4-api)).
- Define one catalog read service used by ingestion, manual matching, and editor navigation. It returns provider series, available orders, seasons, episodes, stable episode IDs, order-scoped positions, names, air dates, and image references, with explicit source and freshness. The chosen order is a per-show setting, not a media-type special case.

### B. Series, season, and episode editor (walkthrough 1–4)

- Series scope searches and confirms a TheTVDB show, using an existing trusted `tvdb_id` bridge first when available. Show source/order selection with a preview of seasons and owned coverage. Keep the current TMDB identity visible separately when present.
- Season scope shows the owned structural season number and the selected catalog season. Allow a direct season match and bounded owned-episode review. Episode scope provides a season selector, title/number filter, and one consistently inset, aligned list of episodes with fixed image placeholders. The search applies to the chosen show's episode catalog, not a generic TV-show search result.
- Confirm exact provider IDs on apply and revalidate them against the selected series/order. Display missing numbers, duplicate titles, absolute-number differences, and occupied local positions clearly. Batch review selects only unambiguous matches; title-only or cross-provider proposals require explicit selection. A single episode can always be corrected individually.

### C. Identity, artwork, and shared ingestion behavior (walkthrough 3–6)

- Retain owned hierarchy and file paths unless the user explicitly edits placement. Confirmed episode identity is the provider episode ID, while S/E and absolute number are order-scoped coordinates. Order changes preview affected matches and preserve exact IDs where possible. Duplicate owned assets may represent the same episode variant, but must not silently claim a different episode.
- Use the same catalog/order resolution in the TV ingestion worker and the editor. Parse local S/E, absolute numbers, titles, and dates as evidence; do not require all to agree. Exact ID and clear order evidence rank above title-only similarity. Keep ambiguous cases in review rather than forcing a match.
- Refresh show, season, and still artwork only for confirmed owned targets. TheTVDB art use must follow the project's approved license. TMDB art can remain available when the corresponding TMDB episode is independently verified by stable ID evidence or a confirmed one-to-one title/date crosswalk; never join by equal S/E numbers alone. Preserve user-selected preferred artwork and report no-image/provider-error separately.

### D. Migration, verification, and rollout (walkthrough 2, 5, 6)

- Inventory current TV identities and claims, including local S/E, TMDB show/episode IDs, existing `tvdb_id`, art ownership, and user overrides. Build a read-only per-show migration preview before any write. Migrate incrementally, with idempotent operations and a way to leave a show on its existing order.
- Test with Solo Leveling aired and absolute orders, a non-anime aired/DVD discrepancy, season 0 specials, episodes with repeated/translated titles, missing provider images, provider outage, and old TMDB matches. Verify exact IDs after reopen and unchanged owned-only detail lists, files, progress, and preferred artwork.
- Build and run focused provider/API/editor tests, then inspect the rendered editor at desktop and mobile widths. Roll out TheTVDB as an optional provider until credentials, licensing, migration, and artwork behavior are verified. Document the offline behavior: cached library browsing works; new provider matching waits for connectivity.

## Scope boundary

The plan does not request a hosted Tuvima metadata proxy, a production TheTVDB account, an embedded API key, a bulk rewrite of existing TV records, or importing unowned catalog episodes. Those are separate infrastructure or data decisions. The earlier custom TMDB picker and offset implementation has been removed from the working tree; its commits remain in Git history for audit and recovery.

## Plain-English completion summary

The TMDB-specific matching detour has been backed out. The replacement plan treats season and episode order as a choice for every TV show, with TheTVDB as a useful source when Tuvima has approved API access. Sonarr works through its own online metadata proxy; Tuvima currently does not have one and should not hide a shared key in the local app.
